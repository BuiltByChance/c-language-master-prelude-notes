# 003 · 故事1：C 的来历与它用在哪里

**C 是语言，Unix 是操作系统。** 在贝尔实验室开发早期 Unix 的过程中，肯·汤普森从 BCPL 发展出 B，丹尼斯·里奇又给 B 增加类型等特性，形成 C。里奇记述的形成期是 1969–1973 年，1972 年尤为关键。课上口述的“80 年代”对应的是 C 日益普及的时期。两人于 1983 年共同获得图灵奖。[里奇回顾 C 的发展](https://cm-bell-labs.github.io/who/dmr/chist.html) · [ACM 图灵奖记录](https://awards.acm.org/binaries/content/assets/awards/awards-booklet-2024.pdf)

**Linux 是另一个类 Unix 内核。** 林纳斯·托瓦兹于 1991 年发布早期版本。内核管理处理器、内存等资源，完整系统还包括命令行工具、库和应用。判断手机用了什么内核，要查具体系统：Android 内核基于 Linux，iOS 和 macOS 使用 XNU。[Linux 0.01 发布说明](https://cdn.kernel.org/pub/linux/kernel/Historic/old-versions/RELNOTES-0.01) · [Android 内核](https://source.android.com/docs/core/architecture/kernel) · [Apple XNU](https://github.com/apple-oss-distributions/xnu)

## 如何判断一个功能是不是用 C 写的

1. **先看仓库的范围。** GitHub 项目页的 **Languages** 给出仓库整体的语言统计。课堂打开 MySQL 时显示 C++ 75.6%、C 15.8%，由此能判断该仓库用到了两种语言。要确定数据库的某个模块用哪种语言，还得进入那个模块。[GitHub 对语言统计的说明](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-repository-languages)
2. **找到功能的实现文件。** 讲师在 `torvalds/linux` 打开 **kernel → bpf → bpf_cgrp_storage.c**，能在源码中找到 `#include <linux/bpf.h>` 和 `bpf_cgrp_storage_busy`。他又打开电源管理的 `kernel/power/main.c`。这是两个子系统实际使用 C 的证据。课堂做到阅读源码，没有编译内核。[BPF 源文件](https://github.com/torvalds/linux/blob/052d534373b7ed33712a63d5e17b2b6cdbce84fd/kernel/bpf/bpf_cgrp_storage.c) · [电源管理源文件](https://github.com/torvalds/linux/blob/052d534373b7ed33712a63d5e17b2b6cdbce84fd/kernel/power/main.c)
3. **区分“用到了”和“全部用”。** MySQL 的存储引擎是讲师口头举的例子。整理者核对了 InnoDB 缓冲池的 `buf0buf.cc`，里面使用 C++ 容器，这能确认这部分有 C++ 实现。同理，Linux 主要用 C，也包含其他语言：0.01 的启动文件已经有汇编，6.1 合入的是初步的 Rust 支持。[MySQL 手册](https://docs.oracle.com/cd/E17952_01/mysql-8.4-en/features.html) · [InnoDB 缓冲池](https://github.com/mysql/mysql-server/blob/mysql-8.4.0/storage/innobase/buf/buf0buf.cc) · [Linux 0.01 启动汇编](https://kernel.googlesource.com/pub/scm/linux/kernel/git/nico/archive/+/v0.01/boot/head.s) · [Rust 合入 Linux 的提交](https://github.com/torvalds/linux/commit/8aebac82933ff1a7c8eede18cab11e1115e2062b)

这个方法也适用于解释型语言。问“Python 用什么语言写”，要先指明是用户的 Python 程序，还是负责运行它的解释器。CPython 是主要用 C 实现的 Python 参考解释器。讲师还浏览了服务器 NGINX、Apache HTTP Server，数据存储软件 Redis、PostgreSQL，以及多媒体工具 FFmpeg 和 VLC 的介绍。FFmpeg 的命令行是网页截图，不能据此判断转码是否成功或运行有多快。[Python 官方术语表](https://docs.python.org/zh-cn/3/glossary.html#term-CPython) · [FFmpeg 项目说明](https://ffmpeg.org/about.html)

## 命令、提交和标准分别告诉你什么

- **在命令提示符里输入的是文本。** 讲师在 Windows 打开 `cmd`，输入 `dir` 后列出所在目录，课堂示例为 0 个文件、13 个目录。`ls` 和随手输入的一串 0、1 在他的环境中都报“无法识别命令”。这只说明命令解释器没有找到对应命令。判断一段二进制能否当作机器指令执行，还需要知道指令集和编码。
- **要重查旧代码，认 Git 提交。** Git 提交保存当时已跟踪内容的快照，GitHub 可以托管这些提交。产品版本如 `3.2.1` 和 `3.2.0` 之间可以有许多次提交。读某次旧实现，需定位对应的提交或指向它的标签。讲师画图说明“做到第 100 次提交仍能查看第 3 次”，没有现场回退。[Git 官方书：快照与历史](https://git-scm.com/book/en/v2/Getting-Started-What-is-Git%3F)
- **要确定语言规则，认标准号、年份和状态。** ANSI 在 1989 年批准 C 标准，ISO 于 1990 年采纳技术内容相同的国际标准，因此会见到 C89、C90 两个名字。视频打开的是 ISO/IEC 9899:2018，当时标价 216 瑞士法郎，讲师没有购买。2026-11-19 核实，该版已撤销，替代者是 **ISO/IEC 9899:2024（C23）**。维护旧项目时仍要按项目实际使用的标准解释源码。[GCC 对 C 标准的说明](https://gcc.gnu.org/onlinedocs/gcc/Standards.html) · [ISO 2018 版](https://www.iso.org/standard/74528.html) · [ISO 现行版](https://www.iso.org/standard/82075.html)
