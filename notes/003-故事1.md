# 003 · 故事1：C 的来历与它用在哪里

C 在早期 Unix 的开发中从 B 演化而来。今天想知道一个软件哪里用到了 C，可以从仓库的语言标签找到线索，再打开具体子系统的源文件核对。讲师在 Linux 内核里做到了这一步，在 MySQL 等项目上主要浏览了介绍页和仓库概览。

## 把人物、语言和系统放回时间线（00:00–04:51，07:03–11:14）

| 时间 | 值得记住的关系 |
| --- | --- |
| 1969–1973 年 | 在贝尔实验室，肯·汤普森（Ken Thompson）和丹尼斯·里奇（Dennis Ritchie）参与开发 Unix。汤普森从 BCPL 发展出 B，里奇在 1971–1973 年为 B 增加类型等特性、写出早期 C 编译器，形成 C。讲师口头说成两人在“80 年代”一起创造 C。画面条目把 80 年代写作 C 应用日渐广泛的时期。具体分工和年代可对照里奇本人的回顾。[里奇《The Development of the C Language》](https://cm-bell-labs.github.io/who/dmr/chist.html) |
| 1983 年 | 汤普森与里奇共同获得 ACM 图灵奖。授奖理由涉及操作系统理论，特别是 Unix 的实现。[ACM 图灵奖授奖记录](https://www.acm.org/binaries/content/assets/awards/about-the-acm-a.m.-turing-award-fact-sheet.pdf) |
| 1989–1990 年 | ANSI 于 1989 年批准 C 标准，ISO 于 1990 年采纳技术内容相同的国际标准，常称 C89、C90。讲师用“流行词需要共同释义”比喻标准的作用。同一段代码要在不同工具上得到约定的解释，各方得先约定语法和语义。字幕里的“NCC”“ISC”对应画面的 **ANSI C** 和 **ISO C**。[GCC 文档中的 C 标准沿革](https://gcc.gnu.org/onlinedocs/gcc/Standards.html) |
| 1991 年 | 林纳斯·托瓦兹（Linus Torvalds）发布早期 Linux 内核。Unix 与 Linux 是不同项目，Linux 采用类 Unix 设计。讲师用服务器、嵌入式设备举例说明它的影响，也表达了个人对托瓦兹贡献大小的评价。[Linux 0.01 的发布说明](https://cdn.kernel.org/pub/linux/kernel/Historic/old-versions/RELNOTES-0.01) |

## 黑窗口里实际发生了什么（04:51–07:03）

讲师用医院挂号作比喻。人能口头提出需求，写程序还得把办理过程表达成计算机能执行的步骤。挂号系统只是设想。他在 Windows 开始菜单搜索 `cmd`，借命令提示符演示文字交互。

| 实际输入 | 这个 Windows 命令提示符的响应 |
| --- | --- |
| `ls` | 提示无法识别这条命令。自动字幕的“IOS 命令”应读作 `ls`。 |
| `dir` | 列出当前用户目录，末尾显示 0 个文件、13 个目录。 |
| 一串 `0` 和 `1`，然后回车 | 同样报命令无法识别。输入的是一串文本，命令提示符尝试按命令名解释它。CPU 执行的是按指令集编码的机器指令。 |

## 在 Linux 源码里找 C（11:14–16:53）

1. 在 GitHub 打开 `torvalds/linux`。讲师先看项目的 C 语言标记与目录更新时间，再进入 `kernel/bpf/bpf_cgrp_storage.c`。页面当时显示该文件上次提交为“last month”。
2. 文件开头先是许可证与版权注释，再是 `#include <linux/types.h>`、`#include <linux/bpf.h>` 等头文件。讲师圈出 `bpf_cgrp_storage_busy`，拿它和课堂上随手起的 `a`、`b` 对比。初学者即使还读不懂实现，也能认出源文件、头文件和命名所描述的对象。[录屏对应版本的 BPF 源文件](https://github.com/torvalds/linux/blob/052d534373b7ed33712a63d5e17b2b6cdbce84fd/kernel/bpf/bpf_cgrp_storage.c)
3. 再看 `kernel/power/main.c`，确认另一个子系统也有 C 源码。课堂操作到浏览、圈画为止。讲师也提醒，这些文件由众多贡献者共同维护。[录屏对应版本的电源管理源文件](https://github.com/torvalds/linux/blob/052d534373b7ed33712a63d5e17b2b6cdbce84fd/kernel/power/main.c)

**两处技术说法要分清。** Linux 内核主要用 C。讲师把汇编和 Rust 都连到 6.1 版，Linux 0.01 的启动代码中已经能看到汇编，**6.1 对应 Rust 支持合入主线**。这里看的也是内核，完整操作系统还包括用户空间程序。[Linux 内核语言说明](https://docs.kernel.org/process/programming-language.html) · [Linux 项目对 Rust 的说明](https://www.kernel.org/doc/html/v6.12/rust/index.html) · [Linux 0.01 的启动汇编](https://kernel.googlesource.com/pub/scm/linux/kernel/git/nico/archive/+/v0.01/boot/head.s)

讲师还举了手机系统的例子。Android 的内核基于上游 Linux，苹果的 macOS 和 iOS 使用 XNU。嵌入式或车载只是设备的用途，确定某台设备用什么内核，还要看其系统资料。[Android 内核概览](https://source.android.com/docs/core/architecture/kernel) · [苹果的 XNU 源码与说明](https://github.com/apple-oss-distributions/xnu)

## Git 为什么能找回过去的代码（16:53–20:52）

讲师先在百科页画图。假设游戏版本 `3.2.1` 出现问题，开发者要找回 `3.2.0` 或 `3.1.9` 的代码。接着他把例子缩小到一次次提交。即使已经做到第 100 次提交，只要第 3 次提交还在历史中，仍然可以查看当时的项目内容。发布版本可以隔许多次提交，Git 用提交标识来区分这些快照。[Git 官方书中的快照与本地历史](https://git-scm.com/book/en/v2/Getting-Started-What-is-Git%3F)

Git 是托瓦兹发起的分布式版本控制工具，本地仓库就能保存提交。GitHub 提供远端仓库托管和协作，推送可将本地已有的提交传到远端。讲师随后查看 Git 的组织页和 `git/git` 的 C 语言标记。回退、提交到本地和推送都只作了举例，现场操作是在浏览器里查看页面。[Git 源码](https://github.com/git/git) · [GitHub 对 Git 与托管平台的说明](https://docs.github.com/en/get-started/start-your-journey/what-is-github)

## 怎样判断一个项目用了 C（20:52–29:13）

| 案例 | 画面证据与复习要点 |
| --- | --- |
| MySQL | 百科写着“使用 C 和 C++ 编写”。讲师进入 `mysql/mysql-server`，当时 GitHub 显示 **C++ 75.6%、C 15.8%**，随后停止翻看源码。存储引擎、解析器等由哪种语言实现，是他接下来的口述。核对 MySQL 官方手册，整个项目确实使用两种语言。具体到 InnoDB，缓冲池文件 `buf0buf.cc` 中就有 C++ 容器，所以不能用仓库占比判定整个引擎的实现语言。[MySQL 参考手册](https://docs.oracle.com/cd/E17952_01/mysql-8.4-en/features.html) · [InnoDB 缓冲池源码](https://github.com/mysql/mysql-server/blob/mysql-8.4.0/storage/innobase/buf/buf0buf.cc) |
| CPython | 讲师先找 Python 教程和百科，一度说找不到合适的说明，随后确实打开了 CPython 的中英文条目。要问“Python 用什么写”，先明确所指的实现。CPython 是 Python 的参考实现，解释器核心用 C，标准库的大部分用 Python。这段没有运行解释器。[Python 开发者指南](https://devguide.python.org/) |
| NGINX、Redis | 前者以 HTTP 服务器、反向代理为例，后者以键值存储、缓存为例。讲师用关系数据库 MySQL、SQL Server 对照 Redis 的使用方式。现场看的都是介绍页，关于缓存性能的说法来自口述。[NGINX 项目](https://github.com/nginx/nginx) · [Redis 项目](https://github.com/redis/redis) |
| Apache HTTP Server、PostgreSQL | 一个 HTTP 服务器，一个关系数据库。讲师逐个查看百科，对 PostgreSQL 是先猜测、再看页面的语言标记。两个项目都能找到实际的 C 源码。[Apache HTTP Server 源码](https://github.com/apache/httpd) · [PostgreSQL 源码](https://github.com/postgres/postgres) |
| FFmpeg、VLC | FFmpeg 用于音视频编解码、转码、流处理等，VLC 则是用户可以直接使用的播放器。看似在运行的 FFmpeg 命令行是百科里的截图。VLC 条目列有 C、C++、Objective-C，讲师所说“早期纯 C”没有做历史源码对照。[FFmpeg 项目介绍](https://ffmpeg.org/about.html) · [VLC 源码](https://github.com/videolan/vlc) |

**复习方法（整理者归纳）。** 如果问题是“项目有没有用 C”，找一份实际的 C 源文件就有了例证。如果问题是“这个功能是不是用 C 写的”，先定位它的实现文件，再下结论。Linux 的源码浏览和 MySQL 的仓库占比，恰好说明了这两种证据各能回答什么。

## 去哪里查 C 标准（29:13–29:38）

录屏打开了 ISO/IEC 9899:2018 的官方页面，当时状态是已发布、待修订，英文 PDF 标价 **216 瑞士法郎**，讲师没有购买。**2026-11-19 核实**，2018 版已撤销，现行正式版为 **ISO/IEC 9899:2024（C23）**。需要确认版次或查找正式文本时，可以在 ISO 条目中核对标准号、年份和状态。[ISO 现行版](https://www.iso.org/standard/82075.html) · [录屏中的 2018 版](https://www.iso.org/standard/74528.html)
