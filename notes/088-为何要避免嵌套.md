# 088 · 怎样读清嵌套的 if？用会员折扣检查门槛和 else 的归属

## 改比较符，会改变哪一笔订单？

讲师把会员门槛从 `> 100` 改为 `>= 100`，把非会员门槛从 `> 50` 改为 `>= 50`。原来的 `else` 已经接住等于门槛的金额。需求写“超过”时用 `>`，写“满……即可”时用 `>=`。录屏里的注释仍写“超过 100”，代码中的 `>=` 表示“满 100”。

| 身份 | 本节低档 | 本节高档 | 恰好达到门槛时的减免（上一节 → 本节） |
| --- | --- | --- | --- |
| 会员 | 不满 100 元减 5% | 满 100 元减 20% | 100 元时从 5% 变为 20% |
| 非会员 | 不满 50 元无减免 | 满 50 元减 10% | 50 元时从 0% 变为 10% |

讲师接着保留两个 `>=`，把非会员判断从外层的 `else if (cart_total >= 50)` 移入单独的 `else` 块。会员块内只查 100 元，非会员块内只查 50 元。这样改非会员门槛时，只需看外层 `else` 里的金额判断。整理者分别用会员和非会员身份测试了 9 个金额，包括两个门槛及其两侧。两种使用 `>=` 的写法在这 18 组测试中结果相同。

## 两个折扣档能否合并成一个条件？

下面是课堂用来练习读条件的表达式。每组里的条件必须全部成立，两组中任意一组成立就能进入分支。第二组限定的是非会员的闭区间 `[50, 100]`。[Microsoft Learn · C 逻辑运算符](https://learn.microsoft.com/zh-cn/cpp/c-language/c-logical-operators?view=msvc-170)

```c
(is_vip && cart_total >= 100) ||
(!is_vip && cart_total >= 50 && cart_total <= 100)
```

用非会员消费 120 元检验，表达式为假，表中的规则却仍给 10% 减免。即使条件为真，会员买 100 元和非会员买 50 元也分别应减 20% 和 10%。决定是否合并分支，要核对它们覆盖的金额和命中后要做的事。录屏里这个分支只有占位注释。

## 怎么看一个 `else` 属于谁？

不写大括号时，`if` 或 `else` 各自只控制紧跟的一条语句，这条语句可以是另一个完整的 `if / else`。C 把 `else` 配给同一语法结构里最近一个尚未配对的 `if`，缩进不能改变配对。[Microsoft Learn · C 的 if 语句](https://learn.microsoft.com/zh-cn/cpp/c-language/if-statement-c?view=msvc-170)

录屏中外层 `else` 一度标红，原因是会员块还少一个 `}`。补回它之后，内层的单条赋值即使省略大括号也能正确配对。

讲师在会员块里临时写了下面这段。先找每个 `else` 配的是哪个 `if`，再问走到这一层时，前面哪些条件已经为假。

```c
if (cart_total >= 100)
    discount_rate = 0.20;
else
    if (cart_total > 4000)
        discount_rate = 0.70;
    else
        discount_rate = 0.20;
```

最后一个 `else` 配的是 `if (cart_total > 4000)`。但要走到这个判断，会员的购物金额必须先小于 100，不可能再大于 4000。即便买 4001 元，也会在第一项得到 20%。讲师最后删掉了这层判断，补回大括号，将会员低档恢复为 5%。本节展示了编辑过程，控制台没有展示折扣结果。
