# 161 · 名字能在哪里使用，和对象能活多久，有什么区别？

**作用域**看源代码的位置，从声明和大括号判断这一行能否使用某个名字。**生命周期（lifetime）**看执行时间，判断对象的存储是否仍然有效。课中 `main` 直接写另一函数的 `local_var` 会被编辑器标为未定义，原因是 `main` 看不到该声明。编译器可以在程序还没运行时就发现这个问题。[WG14 C11 草案 §6.2.1、§6.2.4](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1570.pdf#page=53)

| 课堂例子 | 何时存在 |
|---|---|
| `demoFunction` 内的普通 `int32_t local_var = 5;` | 每次进入这个函数体都会产生本次调用的自动对象，执行到初始化语句时赋值为 5。返回后本次对象的生命周期结束，再调用会得到新的对象。 |
| 函数外的 `int32_t g_global_var = 10;` | 它有静态存储期，在程序启动前初始化一次，贯穿整个程序的执行；从一个函数返回后仍保留其值。 |
| `#define SIZE 5` | 预处理阶段把使用处的 `SIZE` 替换为 `5`，这里没有为 `SIZE` 创建运行期对象。 |

**选择结果的交付方式**。若调用者只需要函数算出的整数，可用 `return local_var;` 按值返回，调用者接收一份值。若要让调用者在函数返回后持续访问一块存储，则这块存储必须至少活到最后一次使用。把普通局部变量的地址带出其块，随后通过它读取对象，会产生未定义行为。[WG14 C11 草案 §6.2.4](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1570.pdf#page=56)

课堂实跑两行：`demoFunction` 打印局部值 **5**，`main` 打印全局值 **10**，退出码为 0。末段口头列举的两类资源问题也要分清：动态分配的存储在失去最后一个可释放它的指针后会泄漏；文件作用域的大数组则可能一直占用空间到程序结束。视频没有进行动态分配、测量内存或演示崩溃。
