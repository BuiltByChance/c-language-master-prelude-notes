# 172 · 数组里也有 103，怎样区分它和目标变量的地址？

录屏用 `int building_floors[] = {101, 102, 103, 104, 105};` 表示五个住户，另用 `int target_floor = 103;` 保存要找的值。`building_floors[2] == target_floor` 比较的是两个整数，结果为真。给两边分别加一元 `&`，取到的却是两个不同对象的位置。一次录屏里，目标变量地址末尾是 `F7E4`，数组中 103 的地址末尾是 `F7C0`。

### 从值找到元素，再输出它的位置

```c
#include <stdio.h>

int main(void)
{
    int building_floors[] = {101, 102, 103, 104, 105};
    int target_floor = 103;
    size_t count = sizeof building_floors / sizeof building_floors[0];

    for (size_t i = 0; i < count; ++i) {
        if (building_floors[i] == target_floor) {
            printf("found %d at %p\n", target_floor, (void *)&building_floors[i]);
            return 0;
        }
    }
    puts("not found");
    return 0;
}
```

整理者复习版用命中后立即返回来结束查找。课堂用 `found = 1; break;`，在循环结束后仅当 `!found` 为真才报未找到。中途为观察全部元素而注释了匹配逻辑，控制台列出 103 后仍打印“没有找到”，原因是那一版从未给 `found` 赋 1。恢复匹配逻辑后，最终实跑找到住户 103 并以 0 退出。

### 从地址间距看数组布局

若要列出五组值和地址，在循环内无条件执行 `printf("%d %p\n", building_floors[i], (void *)&building_floors[i]);`，并把查找放到另一次遍历中。录屏用 Windows 计算器的“程序员 → HEX”核对，五个地址的末位依次为 `FB98`、`FB9C`、`FBA0`、`FBA4`、`FBA8`，相邻差 4。数组元素连续，本机一个 `int` 占 4 字节；换平台应看 `sizeof building_floors[0]`。另起一次运行时具体地址可以改变。

`%p` 要求实参类型为 `void *`，文本表示由实现决定。讲师去掉转换后在该机也看到了十六进制地址，复习时应保留 `(void *)`。只能在同一次运行中比较本数组元素的布局，不要把本次打印的数字写成下次运行的固定地址。[WG14 C11 草案 §7.21.6.1 的 p 转换](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1570.pdf#page=333)
