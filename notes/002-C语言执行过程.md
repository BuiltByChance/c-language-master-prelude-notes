# 002 · C语言执行过程

要判断程序会输出什么，先找到 `main`，再沿着实际的函数调用读代码。在 Visual Studio 的 `frank_c_001` 项目中，讲师增加了两个普通函数，问候语仍只打印一次。后来他在另一个源文件里增加第二个 `main`，程序在链接时失败。

## 找到正在读的代码（00:00–01:24）

- 编辑区打开的是 `001.c`，工具栏显示 **Debug / x64**。按 **Ctrl+Alt+L** 可打开解决方案资源管理器。项目的 **Source Files** 下原有 `001.c`、`add.c`、`game.c`。
- **显示行号。** 课堂界面中，打开 **Tools → Options → Text Editor → C/C++**，勾选 **Line numbers**，点 **OK**。开场已经有行号，讲师取消勾选后又恢复。随后他指到 **Text Editor → General → Line/Col**，这一项控制编辑位置的行、列信息。若用中文界面，按 **Ctrl+Q** 搜“行号”也能定位设置（整理者据微软文档核实，2026-11-19）。[Microsoft Learn · 在编辑器中显示行号](https://learn.microsoft.com/zh-cn/visualstudio/ide/reference/how-to-display-line-numbers-in-the-editor?view=vs-2022)

## 从源文件到第一条输出（01:24–02:48，09:43–11:40）

讲师把第一行 `#include <stdio.h>` 比作跑步前的“热身”，临时把它复制成四行相同的指令，又恢复成一行。**构建时**，预处理器处理 `#include`，各源文件编译得到的目标文件再链接成可执行程序。**运行时**，从 C 代码的角度看，这个控制台程序从 `main` 进入。增加空行会改变编辑器里的行号，不会增加一条要执行的语句。[Microsoft Learn · 转换阶段](https://learn.microsoft.com/zh-cn/cpp/preprocessor/phases-of-translation?view=msvc-170) · [main 函数和程序执行](https://learn.microsoft.com/zh-cn/cpp/c-language/main-function-and-program-execution?view=msvc-170)

片尾讲师在 `001.c` 上画箭头，按下列顺序读这段程序。

| 画面行号 | 源码 | 在本例中的作用 |
| --- | --- | --- |
| 3 | `int main() {` | 进入主函数，左花括号是函数体的开始。 |
| 5 | `printf("HelloWorld!\n");` | 打印 `HelloWorld!` 并换行。画面中的两个单词之间没有空格。 |
| 7 | `return 0;` | 从 `main` 返回，报告成功。 |
| 8 | `}` | 标记函数体结束。第 4、6 行为空行。 |

这里的“顺序执行”指本例先输出、再返回。讲师也提醒，学到其他控制流程后，执行顺序可能改变。这段是对源码的圈画讲解。

## 写了函数，什么时候会执行？（02:48–04:34）

两次都从 **Debug → Start Without Debugging**（**Ctrl+F5**）运行。`main` 中只有打印问候语和返回的语句。

| 改动 | 现场结果 |
| --- | --- |
| 在 `main` 下方加入 `void apple()`，里面也写一条打印相同问候语的语句。 | 约 03:14，控制台只有一行 `HelloWorld!`，进程退出码为 0。 |
| 把 `apple` 中的文字改成 `apple!`，再加入打印 `red!` 的 `void red()`。 | 约 03:57，仍然只有一行 `HelloWorld!`，进程退出码为 0。 |

这两个函数都没有被调用。第二次运行后，讲师删去了这两个函数。判断一条 `printf` 会不会执行，可以先看它属于哪个函数，再看程序有没有调用到那里。

**生成成功也可能有警告。** 两次生成都是 1 个成功、0 个失败。讲师复制函数体时留下了 `return 0;`。首轮日志对 `apple` 报出 `C4098`，第二轮对 `apple` 和 `red` 各报一次。原因是这两个函数的返回类型为 `void`，却试图返回一个值。自己练习时可以让它们直接执行到右花括号，或用不带值的 `return;`。这是整理者对屏幕警告的说明。[Microsoft Learn · C4098](https://learn.microsoft.com/en-us/cpp/error-messages/compiler-warnings/compiler-warning-level-1-c4098?view=msvc-170)

## 两个源文件都定义 main 会怎样？（04:34–08:14）

1. 在解决方案资源管理器中，右击 **Source Files → Add → New Item…**，把文件名改成 `002.c` 并添加。讲师口头说“文件夹”，实际新增的是同一项目里的 C 源文件。
2. 保留 `001.c` 的 `main`，在 `002.c` 中写下 `#include <stdio.h>` 和第二个 `int main(void)`，函数体里只有 `return 0;`。再次选 **Debug → Start Without Debugging（Ctrl+F5）** 时，Visual Studio 提示生成出错，询问是否运行上次成功的版本。
3. 保持 **Do not show this dialog again** 未勾选，点 **No（否）**。在 **Output → Build** 读诊断。先看第一条链接错误中的符号名，再核对两个目标文件。

```text
002.obj : error LNK2005: main already defined in 001.obj
fatal error LNK1169: one or more multiply defined symbols found
Build: 0 succeeded, 1 failed
```

`001.obj` 已经定义了 `main`，链接器又从 `002.obj` 遇到同名定义。`LNK2005` 指出具体冲突，`LNK1169` 汇总重复定义。课堂上说“一个项目只能有一个 main”，这里的范围是**一起链接成同一个普通 C 控制台可执行文件的代码**。一个解决方案可以包含多个项目，分别生成各自的程序。[Microsoft Learn · LNK2005](https://learn.microsoft.com/zh-cn/cpp/error-messages/tool-errors/linker-tools-error-lnk2005?view=msvc-170) · [Visual Studio 项目和解决方案](https://learn.microsoft.com/zh-cn/visualstudio/ide/solutions-and-projects-in-visual-studio?view=visualstudio)

## 识别旧程序，确认演示停在哪里（06:39–09:43）

讲师回忆，有学员勾选“不再显示”并点了“是”，以后即使生成出错，看到的仍是上次成功版本的输出。课堂上他选的是“否”。他随后临时写了 `runApp()` 举例说明其他环境可能使用不同的入口名，随即删去，这段没有运行。约 09:38，`002.c` 里仍有第二个 `main`。直到片尾，最后一次实际生成的结果仍是链接失败。

**整理者补充（2026-11-19 核实）。** 如果 Visual Studio 2022 总是启动旧版本，可打开 **工具 → 选项 → 项目和解决方案 → 生成并运行**，将“运行时，当出现生成或部署错误”设为 **Prompt to launch（提示启动）**，恢复课堂所见的询问框。若要让自己的练习重新生成成功，应使参与本次链接的代码只保留一个 `main` 定义，再查看新的生成结果。视频没有演示这两项修复。[Microsoft Learn · 配置生成和运行选项](https://learn.microsoft.com/zh-cn/visualstudio/ide/configure-build-run-options?view=vs-2022)
