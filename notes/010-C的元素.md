# 010 · C 的元素：标记、空白字符与 Tab 对齐

读一行 C 代码，可以先找出编译器识别的标记（token），再问空白起什么作用。`int number` 中间的空白隔开类型和名字，`number = 456` 中等号两侧的空格方便人读，行首缩进则让人看出代码属于哪一层。

## 去哪里查“C 的元素”（00:00–06:20）

讲师在 Bing 搜索“微软文档 C语言”，从 Microsoft Learn 的“C 语言文档”展开 **C 语言参考 → C 的元素 → C 标记 → 空白字符**。录屏的文档版本栏为 Visual Studio 2022，可切换中英文对照标题和术语。他还展示了英文教材的一页程序清单，说明自己对照的是中英文第六版《C Primer Plus》。他对翻译质量的评价来自个人阅读体验。复习时可以用英文词找到原条目，再回到代码判断它的含义。[中文《C 的元素》](https://learn.microsoft.com/zh-cn/cpp/c-language/elements-of-c?view=msvc-170) · [英文 Elements of C](https://learn.microsoft.com/en-us/cpp/c-language/elements-of-c?view=msvc-170)

微软这页的七个主题是**标记、注释、关键字、标识符、常量、字符串文本、标点和特殊字符**。“标记”是其中一个主题，点进去才会看到标记的分类。例如，注释有自己的文档条目；在 C 的翻译阶段，每条注释会被替换为一个空格。[微软《C 标记》](https://learn.microsoft.com/zh-cn/cpp/c-language/c-tokens?view=msvc-170) · [WG14 的 C11 委员会草案 §5.1.1.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=29)

## 在一行代码里认出 token（06:20–11:48）

讲师把 Visual Studio 中的 `001.c` 临时删减到一个小程序，留下 `int main(void)`、函数体内的 `int number;` 和 `return 0;`。他先逐个选中 `int`、`main`、左右圆括号等，再把变量那行改成 `int number = 1;`。他也在函数外打过一段英文，编辑器出现红色波浪线；后来他把英文例句写进 `//` 注释，用词与标点类比程序怎样分词。

| 课堂代码片段 | 按词法边界读 |
| --- | --- |
| `int main(void)` | `int`、`main`、`(`、`void`、`)`。两个关键字和函数名各自完整，两侧圆括号各是一个标记。 |
| `int number = 1;` | `int`、`number`、`=`、`1`、`;`，共五个。 |
| 后面写的 `number == 456` | `number`、`==`、`456`。双字符的相等运算符和三位数的整数常量各是一个标记。 |

微软的教学页把关键字、标识符、常量、字符串字面量、运算符、标点符号分列。查 C11 语法时会看到五类，标准将 `=`、`==` 这样的运算符号列在 *punctuator* 中。对照两种写法，代码仍按上表划分。[微软《C 标记》](https://learn.microsoft.com/zh-cn/cpp/c-language/c-tokens?view=msvc-170) · [WG14 C11 草案 §6.4、§6.4.6](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=75)

## 哪些空白能动，怎样验证（11:48–16:54）

微软页列出六种空白字符：普通空格、水平制表符、换行符、回车符、换页符、垂直制表符。判断一个空白能否删掉，要看删掉以后标记、头文件名或注释边界是否改变。[微软《空白字符》](https://learn.microsoft.com/zh-cn/cpp/c-language/white-space-characters?view=msvc-170)

- **词与词之间。** `int number;` 的类型和名字需要分开。连成 `intnumber;` 时，编译器读到的是一个标识符。相比之下，`number=123;` 与 `number = 123;` 的标记相同。讲师建议在赋值号两侧留空格，让读者容易找到被赋值的变量和值。
- **头文件名里面。** 约 12:48，讲师把第一行临时改为 `#include < stdio.h >`，随后恢复 `#include <stdio.h>`。尖括号内的字符用来标识所查找的头文件，添进去的空格会改变这串字符。课上没有对这个临时写法执行构建。[WG14 C11 草案 §6.10.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=182)
- **两条声明之间。** 讲师恢复较长的示例，把左花括号和两条声明挤成一行 `{int number;int number_2 = 123;`。分号依然分隔两条声明。约 **14:19**，他在 **Debug / x64** 配置下选 **Debug → Start Without Debugging**（菜单标有 **Ctrl+F5**）。构建输出为 **1 个项目成功、0 个失败**，可见四条 **C4101**，含义是局部变量未被引用。控制台显示程序以 **退出码 0** 结束，没有打印程序自己的文字。这个结果验证了这两条声明可以共用一行。讲师随后用分行和缩进恢复可读的布局。[微软对 C4101 的说明](https://learn.microsoft.com/zh-cn/cpp/error-messages/compiler-warnings/compiler-warning-level-3-c4101?view=msvc-170)

约 **14:35**，恢复排版时还有一个值得留意的瞬间：`int number_2 = 123;` 一度接在 `// 定义 definition` 后面，整行都显示为注释色。下一刻把声明放回下一行后，编辑器又按代码着色。行注释在换行处结束，这个换行决定了声明是否属于代码。

## 分号触发格式化，回车触发缩进（16:54–19:51）

1. 讲师先紧写 `number=345`。键入分号后，屏幕上变为 `number = 345;`。口述连说了两次“等于”，画面上只有一个赋值号。起变化的是它两侧的间距。他又重打为 `number = 456;`，有意用手敲出两侧空格，作为初学练习。
2. 接着写 `if (number == 456)`。这里的 `==` 比较是否相等，前一行的 `=` 完成赋值。口述中的“尖括号”应按画面读：条件由圆括号 `()` 包围，后面配对的是花括号 `{}`。
3. 他在花括号之间回车，Visual Studio 把光标移到块内缩进位置，屏幕上能看见竖向参考线。讲师称之为“编译器的自动缩进”，实际操作发生在代码编辑器中。[Visual Studio 的编辑器缩进说明](https://learn.microsoft.com/zh-cn/visualstudio/ide/options-text-editor-all-languages-tabs?view=vs-2022)

## Tab 怎么让行尾注释对齐（19:51–27:18）

讲师把 `// 声明 declaration` 和 `// 定义 definition` 移到 `int number;`、`int number_2 = 123;` 两行的末尾，在较短的一行后多次按 Tab，让两个 `//` 落到同一列。**水平制表符会前进到下一个制表位**；即使制表位每四列设一个，从不同列出发，前进的距离也会不同。这就能解释画面里的对齐效果。[ASCII 对水平制表符的定义](https://datatracker.ietf.org/doc/html/rfc20#section-5.2)

讲师用打字机的列对齐解释这个用法，又画了登录表单，类比 Tab 把焦点从用户名移到密码框。表单是屏幕上的手绘示意。他还口头比较了存储开销，课堂没有测量文件大小。**编码例子（整理者补充）**：若文件以 UTF-8 保存，一个水平制表符占 1 字节，四个普通空格占 4 字节；按一次 Tab 实际写入哪一种，要看编辑器设置。[UTF-8 编码规则 §3](https://datatracker.ietf.org/doc/html/rfc3629#section-3)

## 项目里怎样约定缩进（27:18–31:54）

讲师主张由同一项目的成员约定采用制表符还是空格，以及一个制表位按几列显示，并写进项目规范。课堂提到四列、八列；混排在一种设置下看似对齐，换一种宽度就可能错位。他在源码注释里记下这些选择，没有现场改设置。视频最后停在 `if` 块内，单独一行的 `number` 没有分号，状态栏有 **1 个错误标记**。这版代码没有再次构建或运行。

**设置入口（整理者补充，2026-11-19 按 Visual Studio 2022 文档核实）。** 在 **工具 → 选项 → 文本编辑器 → 所有语言 → 选项卡（Tabs）** 可查看“制表位大小”和“缩进大小”。前者决定制表位相隔几列，后者决定每层缩进几列。“插入空格”会将缩进写成空格；“保留制表符”会尽量写入制表符，剩余列用空格补齐。仅凭屏幕上空了四列，不能判断文件里存了几个字符。[Visual Studio 2022 缩进和制表设置](https://learn.microsoft.com/zh-cn/visualstudio/ide/options-text-editor-all-languages-tabs?view=vs-2022)
