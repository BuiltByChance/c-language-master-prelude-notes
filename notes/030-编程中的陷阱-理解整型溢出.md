# 030 · 整型溢出：怎样判断 int 还能不能加一

## 一个值能存下，加一还能存下吗？

在微软文档《C 和 C++ 整数限制》里找 `INT_MIN` 和 `INT_MAX`，能查到课堂所用 MSVC 的 `int` 范围是 −2147483648 到 2147483647。这里 `LONG_MAX` 与 `INT_MAX` 相等，换成 `long` 也存不下 2147483648，`long long` 可以。给不同平台写代码时，用目标环境的 `<limits.h>` 取上下限。[微软整数限制表](https://learn.microsoft.com/zh-cn/cpp/c-language/cpp-integer-limits?view=msvc-170)

| 课堂代码 | 画面与解释 |
| --- | --- |
| `int score = 8898888888888888;` | 常量能用 `long long` 表示。用它初始化较窄的 `int` 时，MSVC 发出 C4305 警告，保留低 32 位，打印出 `119418424`。数值在类型转换时改变。[微软有符号整数转换规则](https://learn.microsoft.com/en-us/cpp/c-language/conversions-from-signed-integral-types?view=msvc-170) |
| `score = 2147483647;` 后打印 `score + 1` | 两个加数都是 `int`，数学结果 2147483648 超过 `INT_MAX`。这次打印出 `-2147483648`，退出代码为 `0`。有符号加法溢出属于未定义行为，C 不保证会得到这个负数，也不要求程序崩溃。[C 标准委员会草案 §6.5.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3220.pdf#page=85) |

无符号运算另有规则。例如 `UINT_MAX + 1u` 的结果一定是 `0`，因为 `unsigned int` 加法按其最大值加一取模。课堂只查了 `UINT_MAX`，这个算式是整理者补充的对照。[C 标准委员会草案 §6.2.5](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3220.pdf#page=52)

## 在加法之前判断

讲师把判断代码留到后课。下面是整理者补充的可运行示例。对于已经存进 `int` 的分数，只有 `INT_MAX` 再加一会超出上限。若先算 `score + 1` 再检查，检查之前就可能已经溢出。

```c
#include <limits.h>
#include <stdio.h>

int main(void) {
    int score = INT_MAX - 1;
    if (score < INT_MAX) {
        printf("%d\n", score + 1);
    } else {
        puts("out of int range");
    }
    return 0;
}
```

在课堂的 32 位 `int` 环境，初值取 `INT_MAX - 1` 应打印 `2147483647`。把初值改成 `INT_MAX` 再运行，应打印 `out of int range`，跳过加法。

## 怎样判断课堂程序是否异常退出？

看调试控制台最后一行的退出代码。讲师后来加入输入调用，两次运行都显示 `0xC0000005`，表示访问违规。讲师口头说没看到报错，画面里确实没有出现他预期的弹窗。移除输入调用后再运行原加法示例，退出代码恢复为 `0`。录像没有定位访问违规发生在哪条指令。[微软异常码说明](https://learn.microsoft.com/en-us/shows/inside/c0000005)
