# 166 · 为什么另一个源文件写了 extern，链接器仍然找不到变量？

课中 `run_app.c` 把函数外的定义改为 `static int g_static_var = 10;`。这里的 `static` 给名字**内部链接**，只有同一翻译单元中的声明才能用这个名字指向该对象。另一文件 `helper.c` 虽有 `extern int g_static_var;`，链接时仍需要一个具有外部链接的定义。两种写法下，原对象都具有静态存储期，生命周期都贯穿整个程序执行。[WG14 C11 草案 §6.2.2、§6.2.4](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1570.pdf#page=54)

### 按诊断中的符号定位问题

在 Visual Studio 打开“视图 → 输出”，选择“生成”。这次 `helper.obj` 报 **LNK2001**，未解析的符号明确是变量 **`g_static_var`**。`LNK1120: 1 unresolved externals` 是总数。另一个 **C4013** 警告指向函数 `try_access_g`，要在调用前提供原型 `void try_access_g(void);`。仅补函数原型无法解决变量链接失败。[Microsoft 对 LNK2001 的说明](https://learn.microsoft.com/en-us/cpp/error-messages/tool-errors/linker-tools-error-lnk2001?view=msvc-170) · [C4013](https://learn.microsoft.com/en-us/cpp/error-messages/compiler-warnings/compiler-warning-level-3-c4013?view=msvc-170)

- **需要跨文件直接读写同一变量**：一个源文件定义 `int g_static_var = 10;`，共享头文件写 `extern int g_static_var;`，参与读写的源文件包含该头文件，并一起链接。
- **需要由单个源文件管理变量**：保留 `static`，在该文件里实现对外的读写函数，在共享头文件里声明这些函数。其他文件只调用函数，不再声明或引用该变量名。

录屏构建显示 **0 成功、1 失败**。VS 随后询问是否运行上次成功生成的程序。片末已删掉定义前的 `static`，附近“仅在本文中可见”的旧注释还在，未见重新生成或运行；判断链接属性应以声明为准。
