# 016 · 注释：行注释、块注释与编译结果

读一段带注释的 C 代码，先找注释在哪里结束。编译前，每条注释会被替换成一个空格，换行保留。只有注释外的代码才可能执行。[WG14《C11 草案》§5.1.1.2、§6.4.9](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=93)

| 要说明的范围 | 写法 | 在哪里结束 |
| --- | --- | --- |
| 一行或行尾 | `// 说明` | 到本逻辑行末。写在语句之后，前面的语句仍然有效。 |
| 可以跨行的一段 | `/* 说明 */` | 遇到第一个 `*/` 即结束。块注释不能嵌套。 |

两种注释都用正斜线 `/`。字符串里的 `//` 是两个普通字符，`\n` 中的反斜线则引出换行。下面是整理者根据课堂操作改写的完整例子。运行后，控制台只打印一行 `HelloWorld!`。

```c
#include <stdio.h>

int main(void)
{
    /* 暂时停用这条输出
    printf("A\n");
    */
    printf("HelloWorld!\n");  // 右边的说明不会被打印
    return 0;
}
```

**课堂验证（03:58–04:49）。** 讲师在 `run.c` 的块注释里写了一句中文，把打印语句留在 `*/` 之后。用课堂的 **Debug / x64** 配置生成并运行，输出窗口显示 1 个成功、0 个失败，控制台打印 `HelloWorld!`。他把中文再复制一份到 `/*` 上方后，编辑器在块外的文字下画出红色波浪线。这次只看到了编辑器诊断，讲师没有为这次改动重新生成。

**怎样定位讲师说的行号。** 录屏里的 Visual Studio 2022 路径是 **工具 → 选项 → 文本编辑器 → 所有语言 → 常规 → 行号**，现场打开时已勾选。使用新版设置界面时，在 **工具 → 选项 → 所有设置 → 语言 → 默认值 → 常规** 勾选“行号”。也可以按 **Ctrl+Q** 搜“行号”。源文件左边栏出现数字即已生效，复制代码时不会带上这些编号。两种界面于 2026-11-19 对照微软文档核实。[微软：在编辑器中显示行号](https://learn.microsoft.com/zh-cn/visualstudio/ide/reference/how-to-display-line-numbers-in-the-editor?view=visualstudio)
