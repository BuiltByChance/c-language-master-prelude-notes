# 042 · 为什么浮点数能精确保存 0.5，却只能近似保存 0.1

## 给一个小数，怎样判断它能不能用二进制写完？

二进制小数点后各位从左到右分别代表 1/2、1/4、1/8……。如果只用 `n` 位就能写完，通分后这个数一定形如 `整数 / 2ⁿ`。因此，把一个有理数化成最简分数，看分母是否为 2 的幂（包括 1），就能判断它的二进制展开是否有限。

| 十进制数 | 最简分数 | 二进制展开 |
| --- | --- | --- |
| 0.5 | 1/2 | `0.1₂`，小数点后第一位就凑足了 1/2。 |
| 0.1 | 1/10 | `0.0001100110011…₂`。分母含因数 5，用多少个二进制小数位都写不完。 |

**手算二进制展开（整理者补充）**

把小数部分乘 2，记下结果的整数位，保留余下的小数继续乘。以 0.1 为例，依次得到 0.2、0.4、0.8、1.6、1.2，记下 `00011`。此时又剩 0.2，接下来会重复产生 `0011`。[0.1 的二进制展开对照](https://docs.python.org/zh-cn/3/tutorial/floatingpoint.html)

课堂在 Windows 计算器的“程序员”模式中选了 `OCT`（八进制），十进制对应 `DEC`。这个模式只接受整数，即使选对进制，也无法用它输入 0.1 核对展开式。[微软计算器项目测试](https://github.com/microsoft/calculator/blob/main/docs/ManualTests.md#L155-L157)

## 二进制能写完，就一定存得下吗？

还要看格式能保留多少位、指数允许多大。课堂的 13.25 可以直接拆成 `8 + 4 + 1 + 1/4`，所以它等于 `1101.01₂`。把小数点左移三位，就得到 `1.10101₂ × 2³`。其中 `1.10101₂` 是有效数，包含小数点前的 1。指数 3 把它放大 8 倍，恢复到原来的数量级。

以 IEEE 754 的 binary32 为例，1 位记录符号，8 位记录指数，23 位显式记录小数部分。正规数的开头默认有一个 1，因此有 24 个二进制有效位。13.25 所需的 6 个有效位和指数 3 都能容纳，可以精确保存。像 0.1 这样的无限展开则要按舍入规则选一个附近的可表示值。格式决定有哪些值可选，舍入规则决定选哪一个。[微软对 IEEE 浮点表示的说明](https://learn.microsoft.com/en-us/cpp/build/ieee-floating-point-representation?view=msvc-170)

## 为什么打印出来仍然是 0.1？

下面是整理者补做的 C 实验。录屏结束时，讲师只在记事本写下了 `float`，把声明和输出留给后续课程。

```c
#include <stdio.h>

int main(void)
{
    float x = 0.1f;
    printf("%.1f | %.9f\n", x, x);
    return 0;
}
```

在 Windows x64 的 TinyCC 上运行得到 `0.1 | 0.100000001`。两处打印的是同一个 `x`。`%.1f` 和 `%.9f` 分别将输出舍入到小数点后 1 位和 9 位，因此第一处恰好显示为 `0.1`，第二处才看出它略大于数学上的 1/10。[printf 的输出精度](https://learn.microsoft.com/en-us/cpp/c-runtime-library/format-specification-syntax-printf-and-wprintf-functions?view=msvc-170#precision)
