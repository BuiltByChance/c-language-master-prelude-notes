# 051 · 5 除以 2 为什么显示 2.0？用最小实验定位原因

5 个苹果分给 2 名学生，`total_apples` 和 `student_count` 都是 `int`。课堂程序用 `double average_apples = total_apples / student_count;` 求平均数，再用 `%.1f` 显示一位小数，屏幕上却是 `average = 2.0`。要分清小数是在计算时丢失，还是在显示时丢失，可以直接打印除法表达式的值。

## 用同一组数做对照

在 Visual Studio 打开「视图 → 解决方案资源管理器」，右击项目的「源文件 → 添加 → 新建项」，命名为 `minimal_experiment.c`。把业务变量换成常量，让每一行只检验一种除法写法。

```c
#include <stdio.h>

int main(void)
{
    printf("int division: %d\n", 5 / 2);
    printf("double division: %.1f\n", 5.0 / 2.0);
    printf("with conversion: %.1f\n", (double)5 / 2);
    return 0;
}
```

如果在原项目里新建文件，两个 `.c` 文件都定义了 `main`，链接会失败。遇到「是否运行上次的成功生成」选「否」，上一次的可执行文件还没有这三行实验代码。到「输出」窗口找 `LNK2005` 后面重复的符号名，本例是 `main`。最后的 `LNK1169` 是重复定义的汇总。课堂把原文件 `wrong_result.c` 的 `main` 暂改为 `main01`，保留实验文件的 `main`。此时可按 Ctrl+F5 运行，核对以下三行读数。[微软链接错误说明](https://learn.microsoft.com/zh-cn/cpp/error-messages/tool-errors/linker-tools-error-lnk2005?view=msvc-170)

| 表达式 | 课堂输出 | 除号两边发生了什么 |
| --- | --- | --- |
| `5 / 2` | `2` | 两个操作数都是 `int`，整数商向零截断，`%d` 显示这个整数。 |
| `5.0 / 2.0` | `2.5` | 两个常量都是 `double`，执行浮点除法，`%.1f` 显示一位小数。 |
| `(double)5 / 2` | `2.5` | 先把 `5` 转成 `double`，另一个操作数 `2` 在相除前也转换为 `double`。 |

原式先算出整数 `2`，再用它初始化 `double` 变量，得到 `2.0`。整理者用同一个 `%.1f` 复测，`(double)(5 / 2)` 显示 `2.0`，`(double)5 / 2` 显示 `2.5`。两次输出格式相同，差别在于转换发生在除法之前还是之后。[C11 委员会草案 §6.5.5 整数除法](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=110) · [§6.3.1.8 算术转换](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=71)

## 把结论带回原程序

讲师把实验文件的 `main` 改为 `main02`，把原文件的 `main01` 改回 `main`。先保留两个整数计数，只改求平均数的一行，重新运行后显示 `average = 2.5`。

```c
double average_apples = (double)total_apples / student_count;
```

讲师又去掉强制转换，把两个计数变量都声明为 `double`，用同一组数再次得到 `average = 2.5`。如果人数和个数要按整数保存，只在求平均数时转换一个操作数，就能同时保留整数计数和小数平均值。

设计下一个实验时，先选一组能区分两种解释的输入。以整理者补充的反例来说，若把苹果数换成 4，整数和浮点除法的商都等于 2，单凭商的数值就看不出差别。用 5 和 2 做对照，每次只改一个可疑因素，再回原程序重跑同一组数。要判断哪些行为在其他平台也有保证，查语言规范。要验证业务公式，再测其他有代表性的输入。
