# 133 · 怎样区分数组越界、元素未赋值和部分初始化？

读数组前，先核对长度与下标，再核对该位置的值从哪里来。假设数组有 5 个元素，合法下标是 0～4。`i < 5` 才能挡住尾端，若 `i` 是有符号变量还要保证 `i >= 0`。录屏中读到范围外时，Visual Studio 的代码分析给出警告。即使程序跑完，C 也不保证越界访问会产生什么结果。

| 定义在函数里的普通局部数组 | 可以确定什么 |
| --- | --- |
| `int a[5];` | 已经有五个元素，各元素未显式赋值前没有可依赖的初值。先写 `a[1] = 8;`，就能读第二项，其他四项仍需分别处理。 |
| `int a[5] = {1, 2};` | 五个元素依次是 `1, 2, 0, 0, 0`。前两个由初值列表给出，后三个由 C 的规则补零。 |
| `int a[5] = {0};` | 第一个元素显式设为 0，其余四个补零，一共五个 0。 |

录屏运行部分初始化的数组得到 `1, 2, 0, 0, 0`。讲师推测换编译器可能不补零，这一点与 C 标准不符。只要提供了大括号初值列表，未列出的整数元素就应为 0。对照之下，去掉整个初值列表才是表格的第一种情况。[C11 委员会草案 §6.7.9 第 21 段](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=159)

单独定义普通定长数组时，若方括号里明确写长度，该整数常量表达式必须大于 0。`int a[1];` 合法，唯一的下标是 0。录屏展示的错误例子长度是 `-1`，字幕漏掉了负号。[C11 委员会草案 §6.7.6.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=148)
