# 097 · 怎样判断“是否周末”能从入场条件里删掉？

对已经取好值的布尔变量，可以固定其余输入，只改变待检查的变量。如果对其余输入的每一种取值，结果都不变，这个条件就不影响决定。课堂示例中，`is_weekend` 表示是否周末，`has_invitation` 表示是否持有邀请函。

```c
bool can_enter_club = (is_weekend && has_invitation)
                   || (!is_weekend && has_invitation);
bool can_enter = has_invitation;
```

下表是整理者用 C 程序逐一比较两行表达式的结果。

| 有邀请函吗 | 日期 | 原式能入场吗 | 只看邀请函能入场吗 |
| --- | --- | --- | --- |
| 没有 | 非周末 | 否 | 否 |
| 没有 | 周末 | 否 | 否 |
| 有 | 非周末 | 是 | 是 |
| 有 | 周末 | 是 | 是 |

两个分支都要求有邀请函，而“周末”和“非周末”覆盖了所有日期，所以可以只检查 `has_invitation`。如果规则还要求场地只在周末开放，非周末持函者也要被拒绝，此时应保留 `is_weekend && has_invitation`。

如果入场结果只用来决定是否继续执行，可以省去中间变量，把拒绝条件直接写在 `main` 里。

```c
if (!has_invitation) {
    return 0;
}
/* 有邀请函时，后续入场操作写在这里。 */
```

录屏停在这条卫语句，后续操作留空，也没有打印提示。把 `has_invitation` 改名为 `h` 不会减少任何一次判断，却会让读者必须回头查 `h` 表示什么。

**化简与短路解决不同的问题。** 在本例中，化简后连 `is_weekend` 的值都不必读取。短路只涉及一次求值。`&&` 的左侧为假，或 `||` 的左侧为真时，本次不会计算右侧，即使换一组输入后右侧仍可能决定结果。[Microsoft Learn：C 逻辑运算符](https://learn.microsoft.com/zh-cn/cpp/c-language/c-logical-operators?view=msvc-170)

如果经理、员工和实习生各有独立的权限规则，角色就会改变结果，应保留角色判断。新增角色时加一个 `case`，调整已有角色的门槛时改对应函数。课堂在这里口头回顾了[第 93 节的角色分支](093-switch-case的用途.md)。
