# 083 · 第三章结束语：读表达式、查类型转换、练改错题

## 读一条语句，分别写下结果和变量的变化

课本里的 `6 + (c = 3 + 8)` 有两个数值得分清。`c = 3 + 8` 把 `11` 存进整型变量 `c`，这个赋值表达式的值也是 `11`。外层加法因此得到 `17`，`c` 仍是 `11`。若随后计算 `c > 3`，结果是 `1`，比较本身不会改写 `c`。括号和优先级用来确定分组，不能单凭分组断定各操作数的求值先后。[微软 C 运算符优先级表](https://learn.microsoft.com/zh-cn/cpp/c-language/precedence-and-order-of-evaluation?view=msvc-170)

讲师说“每个表达式都有一个值”，这适用于上面的算式。C 的 `void` 表达式没有可用的值，例如调用一个返回 `void` 的函数，可以执行调用，却不能把它的结果赋给 `int` 变量。[C11 草案 §6.3.2.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=73)

`3 + 4;` 是表达式语句，算出的 `7` 被丢弃，也没有变量改变。单独的 `;` 是空语句，不执行任何操作。`{ ... }` 能把多条语句组成一条复合语句。读 `while` 时就看它后面那一条语句。如果赋值和 `printf` 都包在循环体的花括号里，两者每轮都执行。如果循环体只有赋值，后面的 `printf` 要等循环结束才执行。[C11 草案 §6.8.2–3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=165)

## 类型转换出现意外结果，查哪一行？

赋值时，右侧的值会转换成左侧变量的类型。显式写成 `(目标类型)表达式`，转换就发生在这个位置。书页上的 `(int)1.6 + (int)1.7` 先分别舍去小数部分，得到 `1 + 1 = 2`。若先求和再把结果赋给 `int`，得到的整数是 `3`。[C11 草案 §6.3.1.4](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=69)

在 Microsoft Learn 的「C 语言参考 → 类型转换 → 赋值转换」按**源类型**进入，再在表中找**目标类型**。例如页面用 `int i = -3;` 给 `unsigned short u` 赋值。此例中 `unsigned short` 的范围是 `0` 到 `65535`，转换按模 `65536` 取值，故 `u` 是 `65533`。这个数出现在文档的示例注释里。[赋值转换入口](https://learn.microsoft.com/zh-cn/cpp/c-language/assignment-conversions?view=msvc-170) · [从带符号整型转换的示例与表格](https://learn.microsoft.com/zh-cn/cpp/c-language/conversions-from-signed-integral-types?view=msvc-170)

读浮点表还要看适用的编译器。录屏选的是 Visual Studio 2022，讲师圈出“Microsoft 专用”。核实于 2026-11-22，该页仍说明 MSVC 的 `float` 用 binary32，`double` 和 `long double` 都用 binary64。转成 `float` 时，能精确表示的值保持不变，其余值受舍入和范围限制。默认舍入到最近值，恰在中点时取尾数为偶数的一侧。发生上溢时，文档给出的结果是与原数同号的无穷。换用其他编译器，要查该实现的说明。[微软浮点转换说明](https://learn.microsoft.com/zh-cn/cpp/c-language/conversions-from-floating-point-types?view=msvc-170)

## 用改错题检验自己会不会写

讲师建议先做能用已学知识解出的题，涉及未学循环的练习可以留到以后。改完后，重新输入修正版，用同一组输入运行，核对预期输出，再回到原题指出哪一行导致差异。重复敲课堂案例时，每遍都要能解释关键语句为什么这样写。这节课只圈出了含 `while` 的改错题，未现场给出修正版或运行结果。

讲师用按位异或说明他选案例的标准。学完既能算出结果，也能说出在开发中什么时候会用它。谈到短期上岗训练时，他建议为长期学习补上内存机制、编译原理和设计理由。选课时可以看示例是否讲到这些内容。
