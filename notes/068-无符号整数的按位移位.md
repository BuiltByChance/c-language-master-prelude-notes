# 068 · 13 左移一位为什么得 26，右移一位为什么得 6？

`x << k` 把 `x` 的二进制位向左移 `k` 位，`x >> k` 向右移 `k` 位。`k` 表示移动几位。课堂用 `unsigned int value = 13u;`，后缀 `u` 使这里的常量 `13` 具有 `unsigned int` 类型。两次移位都从原值 `13` 开始，分别把结果存入 `left` 和 `right`，用 `%u` 按无符号十进制打印。表中省略了二进制数前面的高位零。

| 课堂代码 | 二进制怎样变化 | 控制台输出 |
|---|---|---|
| `unsigned int left = value << 1;` | `1101` 左移，右端补 `0`，得 `11010`（16 + 8 + 2） | `13 << 1 = 26` |
| `unsigned int right = value >> 1;` | `1101` 末尾的 `1` 移出，左端补 `0`，得 `0110`（4 + 2） | `13 >> 1 = 6` |

对 `unsigned int`，每左移一位，各个 `1` 的位权都翻倍。左移 `k` 位相当于乘以 2ᵏ，只保留类型容得下的低位。右移 `k` 位得到除以 2ᵏ 的整数商。`13 ÷ 2` 余下的 `1` 正是图中移出的最低位，因此右移结果是 `6`。[C 移位规则 §6.5.7](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=113)

## 移出的高位和越界的位数怎么区分？

先检查 `k`。它必须大于等于 0，且小于**整数提升后左操作数的位宽**。课堂使用的 Microsoft C 中，`unsigned int` 的 `UINT_MAX` 为 4294967295，即 2³² − 1，所以 `k` 可以是 0 到 31，移 0 位保留原值。换平台可查 `<limits.h>` 的 `UINT_MAX`，C 只保证它至少为 65535。若左边改用 `unsigned char`，而 `int` 能表示它的全部取值，它会先提升为 `int`，此时按 `int` 的位宽检查。[移位计数 §6.5.7](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=112) · [C 整数范围 §5.2.4.2.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=45) · [微软整数范围](https://learn.microsoft.com/zh-cn/cpp/c-language/cpp-integer-limits?view=msvc-170)

以 32 位 `unsigned int` 为例，`0x80000000u << 1` 的移位量合法，唯一的 `1` 从最高位移出，结果是 `0`（整理者复测）。而 `13u << 32` 和 `13u >> -1` 的移位量越界，行为未定义，不能据此预测会得到零或改向移位。

只需把数翻倍时，写 `x * 2` 能直接表达目的。要控制哪些二进制位被移出或腾空时，写移位。课堂没有比较两种写法的运行时间，性能差异需要在目标平台实测。
