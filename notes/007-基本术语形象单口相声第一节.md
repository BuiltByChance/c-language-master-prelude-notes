# 007 · 基本术语形象单口相声第一节（理解即可）

买彩票和备考的例子说明程序怎样选路、重复和停止。门诊与放射科的分工说明谁调用函数、谁接收返回值。读这段 C 代码时，先找入口，再沿实际执行的那条路往下看。

## 从教材图读懂一段程序（00:00–02:18）

## 删去头文件后，生成停在哪里（12:59–16:31）

讲师把头文件比作应聘时带的“证书”。在这段 C 代码里，具体作用是让编译器看到函数声明。`<stdio.h>` 声明了 `printf` 和 `scanf`，前者向标准输出写入格式化内容，后者从标准输入读取。本例实际只调用了 `printf`。[WG14 C11 草案 §7.21.6.3–4](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=342)

1. **清理草稿并发起运行。** 讲师保留 `number` 和 `printf`，删去文件开头的两条 `#include`。在 `Debug`、`x64` 配置下，选择 **Debug → Start Without Debugging**（Ctrl+F5）。
2. **区分警告和失败原因。** 约 13:41，生成结果为 0 个成功、1 个失败。编译器先给出 `C4013`，表示没看到 `printf` 的声明，暂按返回 `int` 的外部函数处理。链接器随后报 `LNK2019`，无法解析 `main` 所引用的 `printf`。最后的 `LNK1120` 汇总为 1 个未解析符号。这是讲师这次工程的诊断结果。[Microsoft Learn · C4013](https://learn.microsoft.com/en-us/cpp/error-messages/compiler-warnings/compiler-warning-level-3-c4013?view=msvc-170) · [LNK2019](https://learn.microsoft.com/en-us/cpp/error-messages/tool-errors/linker-tools-error-lnk2019?view=msvc-170)
3. **核对演示的终点。** 讲师在是否运行上次成功版本的弹窗选 **No**。约 14:05，两条包含指令已经恢复，稍后悬停在 `printf` 上能看到函数签名。录像没有展示恢复后的重新生成或控制台输出。

随后他对照英文版图 2.1，在百度翻译输入 `preprocessor instructions`。屏幕译作“预处理器指令”，与中文版图中文字一致。写程序时要认得这里举的具体指令 `#include`。

## 用门诊和拍片理解函数（16:31–25:39）

讲师把 `function` 解释为“能替你做一件事的功能”。他展示的必应词典卡片列出“用途、作用”和数学上的含义，数据来自 Oxford Languages。“功能”是他的记忆方法，教材中的编程术语是**函数**。

- **入口和调用。** 把 `main` 想成门诊挂号。门诊需要影像检查时，请放射科拍片，就像一个函数调用另一个函数。调用方只需知道请谁做什么，设备和内部步骤由被调用方负责。
- **识别函数。** `printf(...)` 是一次函数调用。讲师提示可以留意名字后面的括号。复习时还要看括号前的词，`if (...)` 和 `while (...)` 分别是选择语句和循环语句。[WG14 C11 草案 §6.8.4–5](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=166)
- **返回给谁。** 放射科完成检查，把报告交回门诊，由门诊依据报告继续处理。对应到 C，带表达式的 `return` 结束当前函数，把值交给调用方。讲师在记事本列了七个占位步骤，用 `return xxx;` 表示交回报告，用 `x` 表示接收结果。片末回到教材图，本节没有编译这个“拍片子”草稿。[WG14 C11 草案 §6.8.6.4](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=171)
