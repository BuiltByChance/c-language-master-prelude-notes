# 135 · 为什么一周最高温会算出负二十多亿度？

录屏用七个数表示每天的最高温度，单位为摄氏度，依次是 `22, 24, 19, 24, 17, 18, 23`。总和为 147，所以 `147 / 7 = 21` 是这七个日最高温的平均值。列表里的 17 是最低的**日最高温**，由这批数据无法推算每日夜间最低温。

第一次运行竟显示最高 `-2147483648 °C`。问题出在 `uint32_t max_temp = INT_MIN;`。在录屏环境里，`INT_MIN` 是 `-2147483648`，转为 `uint32_t` 得到 `2147483648`，七个温度都无法大过它。输出又对无符号变量用了有符号的 `%d`，屏幕上的负数不能当作可移植结果。修复时从第一条实测值开始找极值，并让变量类型和输出格式匹配。[C11 委员会草案 §6.3.1.3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=69)

下面是整理者按录屏改写的例子，用带符号的 `int` 保存气温和累加值，也能处理零下气温。七个整数取自课堂。

```c
#include <stdio.h>

int main(void)
{
    const int temperatures[] = {22, 24, 19, 24, 17, 18, 23};
    int highest = temperatures[0], lowest = temperatures[0], sum = 0;
    for (int day = 0; day < 7; ++day) {
        int t = temperatures[day];
        sum += t;
        if (t > highest) highest = t;
        if (t < lowest) lowest = t;
    }
    printf("平均 %.2f，最高 %d，最低 %d\n", (double)sum / 7, highest, lowest);
    return 0;
}
```

录屏把最高、最低都改用第一个元素作初值，再次运行得到 `21.00 °C`、`24 °C`、`17 °C`，退出码为 0。控制台的“最热的天”显示的是温度。若问题问的是**哪天**，还需保留下标，或求出最高值后再遍历列出所有相等项。本例并列最高的是第 2 天和第 4 天。
