# 156 · 判断尾递归，要看调用返回之后还要做什么？

比较两种求和写法。`return n + sum(n - 1);` 要等内层返回，再加上这一层的 `n`。`return sum_tail(n - 1, acc + n);` 在调用之前就把 `n` 加入累计值，内层一旦返回，外层只把同一个结果交回去。后者才是尾递归。

```c
#include <stdio.h>

int sum_tail(int n, int acc)
{
    if (n == 0) return acc;
    return sum_tail(n - 1, acc + n);
}

int main(void)
{
    printf("sum 1..5 = %d\n", sum_tail(5, 0));
    return 0;
}
```

`n` 是接下来还要加的最大整数，`acc` 是已经加好的部分。按 `(n, acc)` 跟踪：`(5, 0) → (4, 5) → (3, 9) → (2, 12) → (1, 14) → (0, 15)`。终止时直接返回 15。连首次和基例在内，源码仍有六次调用；改变的是加法发生的时机。讲师手写了上述实参并提到输出，画面停在源码和手写的 15。整理者独立运行此例，得到 `sum 1..5 = 15`。

这个版本要求 `n >= 0`，并且累加结果能由 `int` 表示。负数继续减 1 无法到达基例。尾递归的形式也不保证栈空间恒定，编译器是否消除调用取决于实现与优化设置。若必须用固定额外空间顺序求和，可以直接写循环，在每轮执行 `acc += n;`、`--n;`。[GCC 的尾调用优化选项](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html#index-foptimize-sibling-calls)
