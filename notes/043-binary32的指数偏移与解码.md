# 043 · 13.25 的 binary32 编码：指数 3 为什么存成 130

IEEE 754 的 binary32 从最高位到最低位依次是符号位 `s`（1 位）、指数字段 `E`（8 位）和小数字段 `F`（23 位）。对于正规数，`s` 决定**整个数的正负**，`E` 以 127 为零点表示**实际指数** `q`。写入时 `E = q + 127`，读回时 `q = E − 127`。[微软 IEEE 浮点表示说明](https://learn.microsoft.com/en-us/cpp/build/ieee-floating-point-representation?view=msvc-170)

## 把 13.25 编成 32 位

1. **换成二进制。** 整数部分 `13 = 8 + 4 + 1`，写成 `1101₂`。小数部分 `0.25 = 0/2 + 1/4`，写成 `0.01₂`。合起来是 `1101.01₂`。
2. **求实际指数。** 把小数点左移三位得到 `1.10101₂`。为保持原值，要乘回 `2³`，所以 `q = 3`。
3. **填写三个字段。** 13.25 为正，故 `s = 0`。指数字段存 `3 + 127 = 130 = 10000010₂`。正规数的有效数以 `1.` 开头，解码时能恢复这个 1，因此 `F` 只存点后的 `10101`，在右侧补 18 个零凑满 23 位。

```text
s   E          F
0   10000010   10101000000000000000000
```

按上面的顺序连接，再每四位分一组，得到 `0100 0001 0101 0100 0000 0000 0000 0000`，即 `0x41540000`。反向核对时，`E = 130` 落在正规数区间 1～254，补回前导 1，得到 `+1.10101₂ × 2^(130−127) = 1101.01₂ = 13.25`。这个数所需的有效位全部放得下，整个过程没有舍入。

换成 `0.5 = 0.1₂ = 1.0₂ × 2⁻¹`，整个数仍是正数，`s` 仍为 0。变化的是 `q = −1`，所以指数字段存 `−1 + 127 = 126 = 01111110₂`。

## 解码时，先看 E，再看 F

8 位共有 256 个编号。binary32 把 0 和 255 留作特殊用途，中间的 1～254（含两端）用于正规数，所以正规数的实际指数从 `1 − 127 = −126` 到 `254 − 127 = 127`。下表中的 `1.F₂` 和 `0.F₂` 表示把字段 `F` 的 23 位接在二进制点右边。[Oracle《数值计算指南》单精度格式，表 2-2](https://docs.oracle.com/cd/E57201_01/html/E57330/z4000ac019178.html)

| E | F | 这些位表示什么 |
| --- | --- | --- |
| 1～254 | 任意 | 正规数，值为 `(−1)^s × 1.F₂ × 2^(E−127)`。隐含的 1 加上 23 位小数，共有 24 位二进制精度。 |
| 0 | 全零 | 有符号零。`s = 0` 得 +0，`s = 1` 得 −0。 |
| 0 | 至少一位为 1 | 次正规数，值为 `(−1)^s × 0.F₂ × 2⁻¹²⁶`。前导位是 0。 |
| 255 | 全零 | 无穷大，正负由 `s` 决定。 |
| 255 | 至少一位为 1 | NaN（非数）。 |

**整理者复核。** 课堂在记事本里手算编码与还原。我另用 TinyCC 在 Windows x64 读取 `13.25f` 的位模式，得到 `0x41540000`。`0.1f` 得到 `0x3DCCCCCD`，其 `E = 123`，也属于正规数，但十进制的 1/10 需要无限个二进制小数位。判断是否有舍入误差，还要看原值能否用这些位精确表示。
