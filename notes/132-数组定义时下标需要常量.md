# 132 · 为什么数组的长度会报“必须是常量”，访问时却能写变量？

在 `int a[5];` 里，`5` 决定建几个元素。在 `a[i]` 里，`i` 决定访问已有的哪一个元素。长度为 5 时，`i` 可在运行中变化，读写时须满足 `0 <= i && i < 5`。

**在课程使用的 MSVC 中定义固定长度数组。** `int n = 5;` 或 `const int n = 5;` 再写 `int a[n];`，编译器都不能把 `n` 当作 C 的整数常量表达式。`const` 限制通过该对象修改值。直接写 `[5]`，或写 `#define SIZE 5` 后用 `[SIZE]`，都能让长度在翻译时确定。宏定义中没有等号和分号。

**换编译器时先看是否支持变长数组（VLA）。** C11 将 VLA 列为可选特性。在支持它的实现里，函数内可以先验证 `n > 0`，再定义自动存储期的 `int a[n];`。进入这次定义时决定长度，之后修改 `n` 不会调整现有数组。微软的符合性表截至 2026-11-24 仍列出 MSVC 不支持 VLA，录屏里的构建错误符合这个编译器的行为。[C11 委员会草案 §6.7.6.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=149) · [Microsoft C 编译器符合性](https://learn.microsoft.com/en-us/cpp/overview/visual-cpp-language-conformance?view=msvc-170#c-compiler-features)

**检查整组初值时，让下标随循环变化。** 以下整理者示例把课程中的两个初始化结果并排输出。

```c
#include <stdio.h>
#define SIZE 5

int main(void)
{
    int zeros[SIZE] = {0};
    int first_one[SIZE] = {1};
    for (int i = 0; i < SIZE; ++i) {
        printf("%d %d\n", zeros[i], first_one[i]);
    }
    return 0;
}
```

第一行是 `0 1`，其余四行都是 `0 0`。大括号中只给第一个整数元素赋初值，未列出的元素会补零。若要五个 1，可写 `{1, 1, 1, 1, 1}`，也可以用循环逐项赋 1。录屏中一度写成 `numbers[2]`，每轮都取第三个元素，改为 `numbers[i]` 才能验证整组。[C11 委员会草案 §6.7.9 第 21 段](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=159)

函数内的普通局部数组可以先定义，再给各元素赋值后读取。录屏去掉初始化后直接读，控制台五行都是 `3435973836`。这是该次调试运行的读数，不能作为元素初值使用。
