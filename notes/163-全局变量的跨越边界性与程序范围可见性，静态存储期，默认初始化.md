# 163 · 为什么两个函数共用一个计数，而另一个源文件找不到它？

课堂在 `1.c` 的函数外写 `int total;`。把**作用域、存储期、链接**分开，就能解释录屏里的三个现象：

| 要判断什么 | 本例中的结果 |
|---|---|
| 当前这行能看见哪个声明？ | `total` 的文件作用域从声明处延伸到本翻译单元末尾。`1.c` 中写在后面的函数能直接使用它；把定义移到 `add_one` 后面，又没有提前声明，前面的函数体就找不到它。函数原型本身可以写在变量声明前。 |
| 每次调用是否产生新的对象？ | 函数外的整数具有静态存储期，即使没写 `static`，它也贯穿整个程序的执行。本例没有显式初始化，进入 `main` 时已经是 0。 |
| 另一份源码能指向同一对象吗？ | 本例的文件作用域定义 `int total;` 具有外部链接。`2.c` 需要自己可见的匹配声明，例如 `extern int total;`；两个翻译单元还须一同链接。若定义改作 `static int total;`，该名字具有内部链接，其他翻译单元无法靠同名 `extern` 指向它。 |

[WG14 C11 草案 §6.2.1–§6.2.4（作用域、链接与存储期）](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1570.pdf#page=53) · [§6.7.9（默认初始化）](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1570.pdf#page=158)

**运行时怎样检查共享状态？** 在第一次调用前打印 `total`，然后每调用一次 `add_one()` 再打印一次。函数体执行 `total = total + 1;`，录屏实测依次是 **0、1、2**。三次读取指向同一对象，首次调用留下的 1 成为第二次加法的起点。

打开 `2.c` 后直接写 `total`，编辑器提示未定义。讲师最后在函数外写好 `extern int total;`，但 `haha(void)` 只返回 0，未调用它完成跨文件读写测试。整理者复习方法：在一个共享头文件放声明 `extern int total;`，让需要它的源文件包含该头文件，只在一个源文件定义 `total`。
