# 013 · 关键字：变量命名、微软扩展与 printf 实测

在 `__int32 number = 123;` 中，`__int32` 指定整数类型，`number` 是程序员给变量起的名字。标准 C 同样给 `int`、`double`、`if` 等词规定了含义，不能再把这些词原样用作变量名。

## 查关键字时先看标准版本（00:30–03:57）

讲师在 Visual Studio 的 `001.c` 中写下 `// keywords 关键字`，随后对照微软文档的中英文版。复习入口是 **Microsoft Learn → C 语言参考 → C 的元素 → C 关键字**。页内把“标准 C 关键字”和“Microsoft 专用 C 关键字”分开列出，标准表的脚注还标明了部分词是在哪一版 C 中加入的。[微软《C 关键字》](https://learn.microsoft.com/zh-cn/cpp/c-language/c-keywords?view=msvc-170)

讲师在必应搜索 `C keywords`，打开微软的结果，也查看了 W3Schools.in 的 32 项表。画面上的 `auto`、`break`、`case`、`char` 等都是关键字，字幕把 `case` 识别成了 `cast`。课上说的 **32 个**对应 C89/C90。C99 增至 **37 个**，C11 增至 **44 个**。例如 `inline` 和 `restrict` 在 C99 加入，`_Generic` 在 C11 加入。判断名字能否使用，应查项目采用的 C 标准和编译器扩展。[WG14 C11 草案关键字表](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=76) · [微软关键字表及版本脚注](https://learn.microsoft.com/zh-cn/cpp/c-language/c-keywords?view=msvc-170#standard-c-keywords)

## 从三个声明看关键字出现的位置（03:57–05:25）

| 在 `main` 里输入的反例 | 怎样读编辑器的反应 |
| --- | --- |
| `int int = 1;` | 第一个 `int` 指定类型。第二个 `int` 仍被识别为类型说明符，悬停可见类型说明符组合无效的提示。 |
| `int double = 1;` | 换成另一个类型关键字 `double`，同样没有给变量取到名字。 |
| `int if = 1;` | `if` 用于条件语句。编辑器在需要变量名的位置提示应有标识符。 |

讲师随后删去反例，没有构建这些声明。指着现有源码时，他把 `include`、`int`、`return` 一起叫作关键字。对照标准，`int` 和 `return` 都在 C 关键字表中。`#include <stdio.h>` 是让预处理器包含标准输入输出头文件的指令，`include` 不在标准 C 关键字表中。网页还提到预处理阶段可做记号替换，课堂没有编写宏。[WG14 C11 草案 §6.4.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=76) · [微软《#include 指令》](https://learn.microsoft.com/zh-cn/cpp/preprocessor/hash-include-directive-c-cpp?view=msvc-170)

## 哪些名字由实现保留（05:25–07:04）

讲师滚动到微软专用列表，选中 `__int32`。他在记事本里列出 Dev-C++、Xcode、VS Code 等环境，口头推断换个编译器就能把这些名字拿来自用。这一段没有切换编译器。按 C 标准，双下划线开头、或下划线紧跟大写字母的标识符始终保留给实现，因此即使某个编译器没有提供 `__int32`，也应避开这个变量名。这个前缀不能用来判断厂商。[WG14 C11 草案 §7.1.3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=200)

据 2026-11-19 核对的微软文档，在 Microsoft C 中，`__int32` 表示 32 位整数，与该实现的 `int` 同义。课程还提到同一组扩展中的 `__int8` 和 `__int64`。普通 `int` 的位宽取决于实现，课堂使用的 Debug、x64 是项目配置。[微软 C 固定大小整数类型](https://learn.microsoft.com/zh-cn/cpp/c-language/c-sized-integer-types?view=msvc-170) · [微软对整数类型范围的说明](https://learn.microsoft.com/en-us/cpp/cpp/data-type-ranges?view=msvc-170)

## 跟着录屏检查 printf（07:04–08:48）

1. 在 `001.c` 的 `main` 中声明 `__int32 number = 123;`，将原来的 Hello World 输出改为 `printf("number = %d\n");`。此时只有格式串。`%d` 需要一个对应的 `int` 实参。
2. 查看编辑器的波浪线。悬停提示 **C6064**，指出 `printf` 缺少整数实参。讲师在编辑阶段发现了问题，没有运行这一版。若执行这种缺参的调用，C 标准规定行为未定义。[微软警告 C6064](https://learn.microsoft.com/zh-cn/cpp/code-quality/c6064?view=msvc-170) · [WG14 C11 草案 §7.21.6.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=327)
3. 在格式串后补上逗号和 `number`，让 `%d` 取到变量的值。

   ```c
   __int32 number = 123;
   printf("number = %d\n", number);
   ```

4. 保持工具栏配置为 **Debug、x64**，从 **Debug → Start Without Debugging（Ctrl+F5）** 运行。构建输出为 1 个成功、0 个失败，控制台显示 `number = 123`，进程退出码为 0。这验证了变量值被传给 `printf`，没有测量整数的位宽。

最后讲师删除 `number` 的声明，恢复 `printf("Hello, World!\n");`，保留 `// keywords 关键字` 注释。本节最后一次实际运行的是打印 123 的版本。
