# 006 · 玩之前的工作：用 printf 输出整数和加法结果

## 让控制台先显示 123，再显示 246

在 Visual Studio 的 C 控制台项目中打开 `001.c`。讲师用的项目名是 `frank_c_001`，工具栏为 `Debug`、`x64`。把原来的问候语换成下面的程序。

```c
#include <stdio.h>

int main() {
    int number = 123;
    printf("%d\n", number);
    return 0;
}
```

1. `int number = 123;` 定义一个整数变量并给它初值。讲师把变量比作有名字的篮子，`number` 是篮子的名字，`123` 是里面放的值。
2. 在 `printf` 的双引号里写小写 `%d` 和 `\n`，引号外用逗号隔开 `number`。`%d` 把后面对应的 `int` 值按十进制输出，`\n` 使后面的文字另起一行。[微软的 printf 格式说明](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/format-specification-syntax-printf-and-wprintf-functions?view=msvc-170)
3. 选 **调试 → 开始执行（不调试）**，英文菜单为 **Debug → Start Without Debugging**，默认快捷键 **Ctrl+F5**。生成成功后，控制台首行应为 `123`。后面“进程以代码 0 退出”是 Visual Studio 显示的退出状态。[Visual Studio 的调试快捷键](https://learn.microsoft.com/zh-cn/visualstudio/ide/default-keyboard-shortcuts-in-visual-studio?view=vs-2022#debug-popular-shortcuts)
4. 只把输出行改为 `printf("%d\n", number + 123);`，再次运行。讲师原先口算成了 456，控制台实际显示 **246**。`+` 先算出 `123 + 123`，再把结果传给 `printf`。这行没有向 `number` 赋值，它仍是 123。

讲师建议把这个短程序手敲 20～30 遍，练习从输入、生成到看控制台的全过程。每次运行前先算出预期值，再用输出检验。

## 第一次运行若遇到重复的 main

课堂第一次生成失败时，`printf` 已经写全。生成输出中的 **LNK2005** 指出 `002.obj` 和 `001.obj` 都包含 `main`，**LNK1169** 汇总重复定义。打开两份对应的 `.c` 源文件，确实各有一个 `main`。此前编辑器在尚未写完的 `printf();` 上显示 **E0165**，那条提示只需补齐实参。[微软对 LNK2005 的说明](https://learn.microsoft.com/zh-cn/cpp/error-messages/tool-errors/linker-tools-error-lnk2005?view=msvc-170)

保留正在练习的 `001.c`。在“是否运行上次成功的版本”提示中选 **No**，以免把旧程序的输出当成这次结果。展开 **解决方案资源管理器 → 源文件**，右击旧的 `002.c` 选 **Remove**。确认框中，**Remove** 仅把它移出项目，适合还要保留旧练习时使用。**Delete** 会删除磁盘文件。课堂选了 **Delete**，再按 **Ctrl+F5** 后得到了 `123`。

讲师建议把这种短程序独立手敲 20–30 遍。每遍先预测控制台会显示哪个数，再运行核对，尤其留意改的是传给 `printf` 的表达式，还是变量本身的值。
