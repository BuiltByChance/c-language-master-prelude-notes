# 006 · 玩之前的工作

用同一个整数变量做两次实验。先让控制台显示变量的值 `123`，再只改 `printf` 的第二个参数，让它显示加法结果 `246`。

## 先输出变量的值（00:00–03:24）

讲师在 Visual Studio 的 `frank_c_001` 项目中打开 `001.c`，工具栏显示 `Debug`、`x64`。他删去原有的问候语输出，保留头文件、`main` 和 `return 0;`，将程序改成下面这样。

```c
#include <stdio.h>

int main() {
    int number = 123;

    printf("%d\n", number);

    return 0;
}
```

1. **给变量一个初值。** `int number = 123;` 定义了名叫 `number` 的整数变量，并把它初始化为 `123`。讲师画了一个叫 `number` 的篮子，把标着 `123` 的苹果放进去。篮子有名字，里面装的是它此刻的值。[Microsoft Learn · 标量初始化](https://learn.microsoft.com/zh-cn/cpp/c-language/initializing-scalar-types?view=msvc-170)
2. **写输出语句。** `"%d\n"` 中的小写 `%d` 把对应的 `int` 值按十进制输出，`\n` 换行。右引号后面写逗号，再写提供这个值的 `number`。讲师提醒用 **Shift+5** 输入百分号。[Microsoft Learn · printf 格式规范](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/format-specification-syntax-printf-and-wprintf-functions?view=msvc-170)
3. **运行并看控制台。** 打开 **Debug → Start Without Debugging**（开始执行，不调试），快捷键 **Ctrl+F5**。课堂第一次生成失败，处理下面的重复入口后再次运行。约 02:54，控制台首行显示 `123`，随后 Visual Studio 提示进程以代码 0 退出。[Microsoft Learn · Visual Studio 默认快捷键](https://learn.microsoft.com/zh-cn/visualstudio/ide/default-keyboard-shortcuts-in-visual-studio?view=vs-2022#debug-popular-shortcuts)

### 课堂上遇到的两个提示

- **01:51，正在编辑。** 写到 `printf();` 时，编辑器提示 `E0165`（调用的参数太少）。讲师随后补齐格式字符串和变量。
- **02:40–02:53，链接失败。** 此时 `printf` 已经写完。生成输出指出 `002.obj` 中的 `main` 已在 `001.obj` 定义（`LNK2005`），错误列表还有 `LNK1169`。讲师在是否运行旧版本的提示框选 **No**，打开上一课的 `002.c`，里面果然也有一个 `int main(void)`。他在 **Solution Explorer → Source Files** 中右击 `002.c`，选 **Remove**，再在确认框点 **Delete**。旧文件从项目中消失，随后生成成功。[Microsoft Learn · LNK2005](https://learn.microsoft.com/zh-cn/cpp/error-messages/tool-errors/linker-tools-error-lnk2005?view=msvc-170)

**复习提示（整理者）。** 遇到同样的重复入口，先按报错中的文件名查找两个 `main`。要保留旧练习源码，可以在上述确认框选 **Remove**，只将它移出当前项目。讲师点的 **Delete** 是永久删除选项。若练习项目中原本就只有一个 `main`，直接运行即可。

## 再输出加法结果（03:24–04:30）

讲师预告后面还会有别的类型，临时敲出 `double number_2;`，随后删去。他没有给这个变量赋值或打印它。

回到整数例子后，他保留 `int number = 123;`，只把输出语句改成 `printf("%d\n", number + 123);`。传给 `printf` 的值是 `123 + 123` 的结果，变量 `number` 本身仍为 `123`。讲师运行前口算成了 `456`。约 04:21，控制台显示 **246**，他随即更正。进程以代码 0 退出。

## 自己练什么（04:30–05:21）

讲师建议先看清输入过程，再按规范手敲这类短程序至少 20 遍，也可以练到 30 遍。练习时留意空格、英文括号和分号，每次从输入走到运行，再看控制台的数值是否与预期相符。
