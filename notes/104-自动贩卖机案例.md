# 104 · 自动贩卖机怎样判断收币、继续投币和找零？

一瓶饮料售价 5 美元，机器只收面额为 1、2、5 的硬币。每次键盘输入代表一枚硬币。用 `coin` 保存**本次面额**，用 `balance` 保存**本次交易已收的总额**。例如，先投 2 再投 2，第二次读到的 `coin` 仍是 2，`balance` 应变成 4。

| 要决定的事 | 检查什么 | 条件成立时做什么 |
| --- | --- | --- |
| 还要投币吗？ | `balance < PRICE` | 进入下一轮，读取一枚硬币 |
| 这枚硬币收吗？ | `coin == 1 \|\| coin == 2 \|\| coin == 5` | 用 `balance += coin` 累加并显示总额。其他面额只提示重投，保留原余额 |
| 要找零吗？ | 循环结束后检查 `balance > PRICE` | 找回 `balance - PRICE`。刚好付清时跳过找零，两种情况都提示取饮料 |

## 在控制台复现

在 Visual Studio 的 C 控制台项目中，将下面的复习代码放入 `.c` 源文件。选择“调试 → 开始执行（不调试）”（`Ctrl+F5`），每次输入一个面额后按回车。[Visual Studio 运行命令](https://learn.microsoft.com/en-us/visualstudio/ide/building-and-cleaning-projects-and-solutions-in-visual-studio?view=visualstudio)

```c
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void)
{
    const uint32_t PRICE = 5;
    uint32_t balance = 0;
    uint32_t coin;

    printf("每瓶饮料 $%" PRIu32 "，只收 1、2、5 三种面额。\n", PRICE);
    while (balance < PRICE) {
        puts("钱不够，请投币：");
        if (scanf_s("%" SCNu32, &coin) != 1) {
            puts("未读到整数，本次交易结束。");
            return 1;
        }

        if (coin == 1 || coin == 2 || coin == 5) {
            balance += coin;
            printf("您已经投入了 $%" PRIu32 "\n", balance);
        } else {
            printf("不接受 $%" PRIu32 " 的硬币，请重新投币。\n", coin);
        }
    }

    if (balance > PRICE) {
        printf("请收好找零 $%" PRIu32 "\n", balance - PRICE);
    }
    puts("谢谢惠顾，请取走您的饮料！");
    return 0;
}
```

录屏的欢迎语写死了价格 5，复习版直接打印 `PRICE`，改售价后提示和结算会同步更新。

录屏写的是 `scanf_s("%" PRIu32, &coin)`。整理者按 C 标准把读取 `uint32_t` 的格式改为 `SCNu32`，打印仍用 `PRIu32`。`&coin` 是本轮读入结果的存放地址。复习版仅在返回值为 1（成功读入一个整数）时检查面额。若首字符是字母或输入已经结束，便终止本次模拟，避免把上一枚硬币重复入账。[C 工作组草案 §7.8.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=235) · [Microsoft Learn 的 scanf_s 返回值说明](https://learn.microsoft.com/zh-cn/cpp/c-runtime-library/reference/scanf-s-scanf-s-l-wscanf-s-wscanf-s-l?view=msvc-170)

## 用输入检查分支

| 输入顺序 | 应观察到的结果 |
| --- | --- |
| `2 → 2 → 5`（课堂实测） | 已收总额依次为 2、4、9。前两次继续要币，最后找 4 并提示取饮料 |
| `10 → 8 → 5`（课堂实测） | 10 和 8 各被拒收一次，仍可继续投币。投入 5 后显示总额 5，直接提示取饮料 |
| `2 → 3 → 1 → 2`（整理者补测） | 拒收 3 后，再投 1 显示总额 3，说明拒币既没有入账，也没有清空先前的 2。最后再投 2，恰好付清 |
