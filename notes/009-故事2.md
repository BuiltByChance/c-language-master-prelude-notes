# 009 · 故事2：读懂 C 标准、版本迁移和语言排行榜

给已有的 C 项目选语言标准，先看代码用了哪些特性、编译器支持到哪一版、团队有多少迁移时间。给自己选要学的语言，先看想做的工作用它解决什么问题。课上的两个例子是一个即将交付的 C11 项目，以及 Python 排第一的 TIOBE 月榜。

## 刚写出 Hello World，需要背 C 的特点吗（00:00–02:17）

讲师在中文百科里选中 C 语言的特点，用刚学会喊“爸妈”的孩子作比喻。初学者先学会表达一件事，等写过字符串、数组，再用具体例子说清语言的特点。这里的 Hello World 是已有知识，课堂没有重新编写或运行它。

## 从 K&R C 到 C23（02:17–06:26，10:18–12:47）

讲师用不同年份的网络流行语比喻规则会变化。C 标准约定程序怎样写、怎样解释。讲师有一句口述说“每年都在更新”。修订工作可以持续进行，正式版之间往往相隔数年。开头屏幕选中的是 **ANSI C**，同句还有 **ISO C**，自动字幕将它们写成了“NCC”“soc”。

| 名称 | 这版值得记什么 |
| --- | --- |
| K&R C（1978） | 《The C Programming Language》第一版描述了当时使用的 C，在正式标准问世前被广泛用作参考。约 11 分钟处的书封署名 **Brian W. Kernighan、Dennis M. Ritchie**。讲师把 K 说成了 Ken Thompson；汤普森的相关贡献包括开发 C 的前身 B。[里奇本人对 B、C 和该书的回顾](https://www.nokia.com/bell-labs/about/dennis-m-ritchie/chist.html) |
| C89 / C90 | ANSI 在 1989 年批准美国标准，ISO 在 1990 年采纳了技术内容相同的国际标准。读到这两个年份，可以先按同一套语言规则理解。[GCC 对 C89、C90 的说明](https://gcc.gnu.org/onlinedocs/gcc/Standards.html) |
| C99、C11、C17 / C18 | C99 引入变长数组和新的整数类型等。C11 增加原子操作和线程支持。2018 年出版的一版主要修正 C11 的缺陷，也称 C17。视频只举出这些变化，没有演示数组或并发程序。[GCC 的 C 标准沿革](https://gcc.gnu.org/onlinedocs/gcc/Standards.html) · [GCC 按标准列出的特性](https://gcc.gnu.org/projects/c-status.html) |
| C2x → C23 | 录屏时中文百科还写着 C2x 正在起草。讲师转到英文资料，打开 WG14 的 N3132 日程，圈出 **2024-02-12 提交文件供出版**，据此预计二月会发布。**2026-11-19 核实**，ISO 记录的实际出版时间为 **2024 年 10 月**，现行第五版编号为 **ISO/IEC 9899:2024**，通称 **C23**。讲师先前举例用的“C24”，在这一段已由他自己澄清为假设。[录屏中的 WG14 日程](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3132.pdf) · [ISO 正式出版记录](https://www.iso.org/standard/82075.html) |

讲师切到英文百科看 B 如何过渡到 C，随后放大 K&R 第一版封面，又搜索“大哥大”展示老式手机。他借这个比喻表达自己的教材选择：读初版可以了解当时的人怎样写 C，他希望学员把日常练习放在较新的标准和工具上。

## 一个 C11 项目，交付前一个月要换标准吗（06:26–10:18）

讲师在百科的 Hello World 示例上画框和箭头。假设一个项目积累了大量 C11 源码，只剩一个月就交付，此时发布新标准，团队要花时间学习新规则、找出要改的代码、确认还能交付。他把可接受的版本下限临时叫作“最低容度”，还特意提醒不用记这个词。**至少学到 C11** 是他给本课程选教材的尺度。当场只画了示意图，没有切换编译器模式或迁移项目。

**兼容性举例（整理者补充）。** 讲师假设未来版本肯定兼容 C11。实际迁移时要查发生变化的规则。例如，旧代码可以把 `nullptr` 用作普通变量名，C23 把它列为关键字；切到 C23 模式编译时，这个变量就需要改名。GCC 也可以显式选择旧标准模式，供项目分步迁移。[GCC 迁移说明中的新关键字](https://gcc.gnu.org/gcc-15/porting_to.html)

**开发工具和考试环境。** 讲师回忆自己上学时大家就在讲 Visual C++ 6.0，转述学生说有学校还在用它，并写下 VC++ 6.0 和 VC++ 2010 作比较。他把 1998 年说成 6.0 的最后更新年份。微软公告记载 6.0 在 1998 年发布，2004 年的 SP6 说明仍列有对 Visual C++ 6.0 的更新。他提到的考试环境也有具体范围，全国计算机等级考试 2023 年版二级 C 大纲列出的是 **Visual C++ 2010 学习版**。课上没有打开这些开发工具。[微软 1998 年发布公告](https://news.microsoft.com/source/1998/09/02/microsoft-announces-worldwide-availability-of-visual-studio-6-0-at-dev-days-98/) · [微软 SP6 说明](https://download.microsoft.com/download/4/9/1/4915E136-7EE3-4D8A-9529-B988266649E6/vstudio_downloads_sp_VS6SP6.pdf) · [教育部教育考试院当年大纲，第 3 页](https://ncre.neea.edu.cn/res/Home/2306/6016844d02b8b7fb5d9ea3981f0a0eb9.pdf)

## 里奇为什么在一句话里说了两次“汇编语言”（12:47–14:06）

英文百科在“局限”一节引用里奇，以“汇编语言的威力”和“……汇编语言的便利”打趣 C。讲师搜索原句，又用 Google 翻译成中文，屏幕上的译文保留了重复。笑点在后半句：听者原本期待听到 C 写起来有多方便，结果又听到了“汇编语言”。讲师接着说 C 比汇编容易读，这是他自己的解释。

随后他打开汇编语言条目，放大一张 **Motorola 6800** 汇编清单。图中能对照看到地址、机器码、指令助记符和注释。他借此说明“靠近机器”指什么，课堂操作停在看图。

## TIOBE 榜首、年度语言和目标岗位（14:06–18:41）

| 录屏中 2024 年 1 月的 TIOBE 月榜 | Python | C | C++ | Java | C# |
| --- | ---: | ---: | ---: | ---: | ---: |
| 排名 | 1 | 2 | 3 | 4 | 5 |
| 评分 | 13.97% | 11.44% | 9.96% | 7.87% | 7.16% |

讲师打开 TIOBE 官网，下滚到表格，指着 Python 说“2023 年年度的语言”。同一页的标题写着 **C# 获 2023 年度语言奖**。月榜比较当月评分，年度奖看过去一年评分涨了多少，C# 当年增加了 **1.43 个百分点**。TIOBE 根据多个搜索引擎的查询命中数计算流行度，表中的百分比不能读作招聘岗位占比。[TIOBE 历届年度语言与评奖规则](https://www.tiobe.com/tiobe-index/) · [TIOBE 指数的计算方法](https://www.tiobe.com/tiobe-index/programminglanguages_definition/)

讲师以培训、少儿编程、金融数据分析为例，说明关注 Python 的人来自多种行业。他回应“Java 不好就业”时提到个人能力和就业环境，又举微软、谷歌、Linux 内核以及 TensorFlow 的例子来谈岗位分工。关于各公司更常用哪种语言、Python 岗位多少，是他的个人判断；录屏里没有查招聘数据或项目源码。

**怎样把岗位问具体（整理者结合官方示例）。** 同是“用 TensorFlow”，用 Python 组合已有运算、编写新的 C++ 算子内核、给内核提供 Python 接口，是三种不同的工作。TensorFlow 官方指南甚至建议先尝试在 Python 中组合已有运算，难以表达或效率不足时再考虑自定义 C++ 算子。选语言时，先把想做的那一层工作说清楚，比照月榜名次更有针对性。[TensorFlow 官方自定义算子指南](https://www.tensorflow.org/guide/create_op)
