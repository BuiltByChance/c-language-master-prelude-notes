# 069 · C17 中，有符号整数移位何时有确定结果？

课堂把 `value`、`left`、`right` 从 `unsigned int` 改成 `int`，先用 `int value = 13u;` 运行，再去掉 `u` 重跑。`13u` 初始化 `int` 时可以精确转换成 `13`，所以两次参与移位的 `value` 都是 `int` 类型的 `13`，控制台也都显示 `13 << 1 = 26`、`13 >> 1 = 6`。录屏沿用了打印无符号数的 `%u`，复写时应让格式匹配结果类型，例如 `printf("%d\n", left);`。

## 先看移几位，再看符号和方向

设 `x` 和 `k` 都是 `int`。`k` 为负或达到、超过 `int` 的位宽时，行为未定义，C 不保证算出哪个值。课堂环境的 `int` 为 32 位，允许移 0 到 31 位。对其他整数类型，这一步看整数提升后左操作数的位宽。[C17 草案 §6.5.7](https://teaching.csse.uwa.edu.au/units/CITS2002/resources/n2176.pdf#page=87)

| 表达式 | C17 怎样决定结果 |
|---|---|
| `x << k`，`x >= 0` | 数学上的 `x × 2ᵏ` 能用 `int` 表示时，结果就是这个乘积。课堂注释中，`3 << 2` 得 `12`，`1 << 30` 得 `1073741824`。`1 << 31` 的位数也合法，但乘积 `2147483648` 比 32 位 `int` 的上限大 1，行为未定义。 |
| `x << k`，`x < 0` | 行为未定义，即使数学乘积能放进 `int`。负数要翻倍且结果可表示时，直接写 `x * 2`。 |
| `x >> k`，`x >= 0` | 取 `x ÷ 2ᵏ` 的整数商。课堂运行的 `13 >> 1` 得 `6`。 |
| `x >> k`，`x < 0` | 结果由实现定义，编译器实现要说明它采用哪种行为。微软 C 用原来的符号位填补左侧空位。 |

**在计算前检查左移是否越界。** 整理者补充的 32 位 `int` 检查式为 `k >= 0 && k < 32 && x >= 0 && x <= (INT_MAX >> k)`。`INT_MAX` 来自 `<limits.h>`，右移后给出还能安全左移 `k` 位的最大原值。把类型转换写在 `(unsigned)(x << k)` 的外层，转换发生在移位之后，无法补救已经越界的移位。

**用负奇数辨别右移和除法。** 按微软文档的补符号位规则，`(-3) >> 1` 得 `-2`，而 C 的整数除法 `(-3) / 2` 向零截断，得 `-1`。这是整理者按文档推算的例子。要按位处理数据时，讲师建议优先用 `unsigned int`。课堂未运行负数示例，也未测量性能差异。[微软 C 的右移规则](https://learn.microsoft.com/zh-cn/cpp/c-language/right-shifts?view=msvc-170) · [C17 草案 §6.5.5](https://teaching.csse.uwa.edu.au/units/CITS2002/resources/n2176.pdf#page=85)

## 在 Visual Studio 确认 C17 模式

打开「项目 → 项目属性 → 配置属性 → 常规」，核对顶部的配置和平台，在「C 语言标准」中选择 `ISO C17 (2018) 标准 (/std:c17)` 并点「确定」。录屏的活动配置为 `Debug / ARM64`，属性页打开时已显示 C17。讲师短暂切到「默认（旧 MSVC）」，随后选回 C17。旁边的「C++ 语言标准」控制 C++ 源文件。课堂的 `wrong_result.c` 使用 C 设置。[微软 C17 配置说明](https://learn.microsoft.com/zh-cn/cpp/overview/install-c17-support?view=msvc-170)
