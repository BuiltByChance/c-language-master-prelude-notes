# 063 · 为什么 x 能接收赋值，x + 1 却不能？

C 中的**对象**是用来保存值的一块存储区域。判断赋值运算符 `=` 的左侧能否接收写入，先问这个表达式指定了哪个对象，再问它是否允许修改。两项都满足，左侧才是赋值所需的**可修改左值**。[对象的定义](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=24) · [赋值的约束](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=119)

| 看左侧 | 指定了什么 | 能否写入 |
| --- | --- | --- |
| `x = 5;`，其中 `x` 声明为 `int x = 3;` | `x` 对象，当前保存 3 | 可以。赋值后，同一对象保存 5。 |
| `limit = 5;`，其中 `const int limit = 100;` | `limit` 对象，定义时已初始化为 100 | `limit` 是左值，但 `const` 限制了修改，不能再赋值。 |
| `(x + 1) = 5;`，其中 `x` 当前为 5 | `x + 1` 得出数值 6，没有指定可写入的对象 | 不能。若目的是让 `x` 增加 1，写 `x = x + 1;`。 |

录屏中，编辑器在 `(x + 1) = 5;` 的左侧标出红色波浪线。给 `limit` 再次赋值只在口头讨论，课堂没有构建或运行这些语句。

括号或加号本身不能决定一个表达式能否接收赋值。例如，声明 `int a[2];` 后，`a[0 + 1] = 5;` 合法，因为左侧整体指定了数组的第 2 个元素。这是整理者补充的对照。

## 为什么右边的 x 也要从左值讲起？

在 `y = x;` 中，右侧的 `x` 先指定对象。此处需要一个数，便从对象中读出当前值，这一步叫**左值转换**。接着才把读出的值写入左侧的 `y`。教材常说的“右值”可以用 `5` 或 `x + 1` 的计算结果来理解。判断依据是表达式的作用，不能只看它写在等号哪边。[C11 的左值、左值转换及脚注 64](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=72)

**整理者复测。** 下面只保留合法语句，将课堂手画的链式赋值也写入程序。

```c
#include <stdio.h>

int main(void)
{
    int x = 3;
    x = 5;
    int y;
    y = x;
    x = x + 1;
    printf("x=%d, y=%d\n", x, y);

    int z;
    x = y = z = 10;
    printf("x=%d, y=%d, z=%d\n", x, y, z);
    return 0;
}
```

第一行输出 `x=6, y=5`。`y` 得到的是复制时读出的 5，后来修改 `x` 不会连带修改 `y`。第二行输出 `x=10, y=10, z=10`。`x = y = z = 10` 按 `x = (y = (z = 10))` 分组。每一层赋值表达式都给出左侧对象赋值后的值，供外层使用。[C11 赋值表达式的值](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=119)
