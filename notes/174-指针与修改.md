# 174 · 两个指针指向同一数组元素时，怎样通过一个修改、从另一个验证？

若 `int *p = &building_floors[2];`，表达式 `p` 的值是该元素的地址，`*p` 则指代元素本身。读整数用 `printf("%d", *p)`；写整数用 `*p = 106;`。给另一个 `int *q` 赋值 `p`，复制的是指针值，两个不同的指针变量都指向同一个整数。

```c
#include <stdio.h>

int main(void)
{
    int building_floors[] = {101, 102, 103, 104, 105};
    int *p = &building_floors[2];
    int *q = p;

    printf("before: %d %d\n", building_floors[2], *p);
    *q = 106;
    printf("after:  %d %d\n", building_floors[2], *p);
    printf("same element: %d\n", q == &building_floors[2]);
    return 0;
}
```

整理者复习版依次显示 **103 103**、**106 106**、**1**。课堂中 `q` 叫 `ptr_new_106`，讲师注释掉直接给数组元素赋值的那行，实际执行 `*ptr_new_106 = 106;`，再打印 `building_floors[2]`，得到 **106**。他把这一步比作“搬家”，代码中改变的是原位置上的内容，数组元素的位置始终相同。

**邻居的地址怎么算？** 从 `&building_floors[1]` 到 `&building_floors[2]` 只需加 **1**，因为 `int *` 加一个单位就前进一个 `int`。录屏试加 **4**，得到的地址与目标不同；在这个五元素数组中，它恰好位于末元素后一位，可以形成该指针，但不能通过它读取元素。这个差异取决于指针的元素类型，与地址用十进制还是十六进制显示无关。[WG14 C11 草案 §6.5.6](https://www.open-std.org/JTC1/SC22/WG14/www/docs/n1570.pdf#page=111)

本例使用的是当前程序自己定义、仍然有效且可写的数组。讲师提到其他程序的游戏分数时只作了口头类比；在 Windows 中，每个进程有自己的虚拟地址空间，课堂的 C 赋值并未展示跨进程修改。[Microsoft 对进程虚拟地址空间的说明](https://learn.microsoft.com/en-us/windows/win32/memory/virtual-address-space)
