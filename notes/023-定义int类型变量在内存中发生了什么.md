# 023 · 定义 int 类型变量时，内存中发生了什么

`int sun_flower = 9673;` 定义了一个名为 `sun_flower` 的整数对象，并把它的初值设为 9673。下一句 `printf("sun_flower = %d\n", sun_flower);` 读出这个值，用十进制打印。**9673 是对象的值。要知道对象占多少字节，需要看它的类型在当前 C 实现上的大小。** 单凭这两行代码，也无法判断编译器最终是否把这个值写入了物理内存。[C 标准委员会草案 §6.7 定义](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=126) · [§6.7.9 初始化](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=158)

课堂还输入过 `float wallet_balance = 99.99;`，用小数举例说明变量名之前可以放其他类型。讲师随后在这行前加上 `//`，留下整数和 `printf` 两行讲解，没有展示本次程序的控制台输出。

**定位代码行。** 在录屏的 Visual Studio 2022 中，打开 **工具 → 选项 → 文本编辑器 → 所有语言 → 常规**，勾选 **行号（Line numbers）** 并确定。讲师先关再开，代码左侧的数字随之消失、重现。新版设置也可按 `Ctrl+Q` 搜索“行号”直接进入（2026-11-19 核实）。[微软的行号设置说明](https://learn.microsoft.com/zh-cn/visualstudio/ide/reference/how-to-display-line-numbers-in-the-editor?view=visualstudio)

## 用任务管理器分清 RAM 与磁盘

一段视频保存在磁盘上，断电后仍可再打开。浏览器打开网页时，正在处理的页面数据会占用 RAM。关闭窗口后，系统可以把不再使用的内存用于别处。普通 RAM 断电后内容会丢失，重启后操作系统会重新占用内存。课堂虚拟机的内存页显示 **8.0 GB**，而 **磁盘 0 (C:)** 页显示虚拟 NVMe 磁盘容量 **70.0 GB**。判断“占了多少空间”时，先确定问的是运行时占用，还是保存文件所需的容量。[NIST 对易失性内存的定义](https://csrc.nist.gov/glossary/term/volatile_memory) · [微软对进程驻留内存的说明](https://learn.microsoft.com/en-us/windows/win32/memory/working-set)

1. 打开 Windows **任务管理器**（可按 `Ctrl+Shift+Esc`）。若是录屏中的简洁视图，先点左下角 **详细信息（More details）**，再选 **性能 → 内存**。[微软的任务管理器入口](https://support.microsoft.com/en-us/windows/experience/system-configuration-tools-in-windows)
2. 看 **正在使用（已压缩）**。括号外是整机当前在用的内存，括号内是其中压缩部分的占用。**可用（Available）** 表示还能供程序使用的内存。
3. 保持观察同一字段，对照打开网页和关闭其窗口后的读数。下表来自讲师机器的两个时点。

| 课堂操作 | 正在使用（其中已压缩） | 可用 | 侧栏内存占用率 |
| --- | --- | --- | --- |
| Firefox 已打开哔哩哔哩首页 | 5.0 GB（416 MB） | 2.9 GB | 64% |
| 关闭这个 Firefox 窗口后 | 4.8 GB（420 MB） | 3.2 GB | 60% |

这次总占用下降，压缩部分却略有增加。两个数要分别读。整机统计还包含系统和其他程序的活动，两次采样的差额无法精确归到这个网页，更无法显示一个 `int` 占了几个字节。

## 从位换算到字节和容量

灯泡的亮、灭可以分别记为 1、0，一个这样的二选一就是一位（bit）。讲师又把活字方阵中的每个位置想成一位，用升起和落下表示两种状态。按固定位置排列，多个这样的状态就能组成图案。换到课堂电脑上，**8 位合成 1 字节（B）**，这 8 个位置共有 `2⁸ = 256` 种组合。

| 容量写法 | 相邻单位的换算 |
| --- | --- |
| 十进制 | 1 kB = 1000 B，1 MB = 1000 kB，1 GB = 1000 MB |
| 二进制 | 1 KiB = 1024 B，1 MiB = 1024 KiB，1 GiB = 1024 MiB |

讲师在画图里写了 `1KB = 1024Bytes`，口头也说过“1000 个字节”。看换算式就能分辨他指哪一种。按标准符号，1024 B 写 **1 KiB**，1000 B 写 **1 kB**。二进制这一列的级差来自 `2¹⁰ = 1024`，字节换成位则要乘以每字节的位数。[NIST 的二进制与十进制前缀对照](https://physics.nist.gov/cuu/Units/binary.html)

## 自己验证一个整数对象有多大

片尾讲师在画图里画了几条横线，准备把一个字节分成格子，讲到想改用 Excel 就结束了。课堂没有查看 `sun_flower` 的地址或逐字节内容。

**整理者补充实验。** 在 C 控制台项目中运行下面的程序。`sizeof sun_flower` 给出该对象在本次编译环境中占的字节数，`%zu` 用于打印这一结果。`<limits.h>` 中的 `CHAR_BIT` 给出一个 C 字节的位数。[C 标准委员会草案 §6.5.3.4 sizeof](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=108) · [§5.2.4.2.1 整数类型的限制](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=45)

```c
#include <limits.h>
#include <stdio.h>

int main(void)
{
    int sun_flower = 9673;
    printf("sun_flower = %d\n", sun_flower);
    printf("bytes = %zu, bits per byte = %d\n", sizeof sun_flower, CHAR_BIT);
    return 0;
}
```

整理者在 Windows x64 上用 TinyCC 实测，第一行是 `sun_flower = 9673`，第二行是 `bytes = 4, bits per byte = 8`。因此这个环境中的 `int` 占 4 个字节、共 32 位。换编译目标时可用同一段代码重新验证。
