# 001 · 第一个程序

在 Visual Studio 中运行一个 C 程序，让控制台显示 `Hello World!`。再把字符串末尾的 `\n` 删掉，观察哪一行发生了变化。

## 写出并运行 hello.c

1. **从已打开的源文件开始（01:30–02:04）。** 课程假定学员已会使用 Visual Studio。讲师在项目 `frank_c_001` 的空白 `hello.c` 中输入下面的代码，工具栏显示 `Debug`、`x64`。他一度把 `return` 敲成 `reutrn`，编辑器标出红色波浪线，他随即改正。
2. **运行（05:40）。** 为了演示行注释，讲师先在 `//` 后随意敲了一串字符。然后打开 **Debug → Start Without Debugging**（调试 → 开始执行，不调试，快捷键 **Ctrl+F5**）。
3. **核对结果（05:42–05:50）。** 生成窗口显示 1 个项目成功、0 个失败。控制台先显示 `Hello World!`，随后 Visual Studio 提示进程以代码 0 退出。程序自己打印的内容到感叹号和随后的换行为止。

下方是讲师删去讲解注释后留给学员练习的八行代码（含空行）。

```c
#include <stdio.h>

int main(void)
{
    printf("Hello World!\n");

    return 0;
}
```

## 顺着这几行读程序

- **`#include <stdio.h>`（02:04–04:41）。** `#` 标出预处理指令，`include` 表示包含。按 `std`（standard，标准）和 `io`（input/output，输入/输出）拆开记，就容易把 `stdio.h` 拼对。`.h` 是头文件常用后缀，课堂上的 `.c` 文件则用来写 C 源代码。这里包含头文件，是为了让编译器看到 `printf` 的声明。[Microsoft Learn · #include 指令](https://learn.microsoft.com/zh-cn/cpp/preprocessor/hash-include-directive-c-cpp?view=msvc-170) · [Microsoft Learn · printf](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/printf-printf-l-wprintf-wprintf-l?view=msvc-170)
- **`int main(void)` 和花括号（04:41–07:18）。** 在这个控制台程序中，从 `main` 进入函数体。`void` 写在圆括号内表示没有参数，开头的 `int` 是返回类型。两层意思可以分开读。花括号 `{ }` 括起函数体，本例先输出文字，再返回。讲师提到其他教材里的写法，短暂改成 `main()` 后恢复原样，运行示例使用的是上面的完整写法。
- **`//` 行注释（05:12–06:09）。** 连续两个正斜杠开始注释，直到本行末尾。讲师一度口误说成“反斜杠”，画面上实际敲的是 `//`。他在后面写说明、随手敲字符，程序仍然成功运行，控制台里也没有这些注释文字。
- **`return 0;`（07:18–07:39）。** 在这里结束 `main`，向运行环境报告成功。讲师要求练习时显式写这一行。按 C99 起的规则，对本例这样的宿主环境程序，执行到 `int main(void)` 末尾的 `}` 也会返回 0。[WG14 C99 草案 N1256，§5.1.2.2.3](https://landley.net/c99-tc3.html#5.1.2.2.3)
- **`printf("Hello World!\n");`（07:39–08:17）。** `printf` 做格式化输出，把双引号内的文字写到标准输出流 `stdout`，这里显示在控制台。`\n` 由一个反斜杠和小写 `n` 写成，表示一个换行。[Microsoft Learn · printf](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/printf-printf-l-wprintf-wprintf-l?view=msvc-170)

## 两次运行怎样看出换行

| 时间 | 讲师运行的语句 | 控制台上看到的结果 |
| --- | --- | --- |
| 08:19 | `printf("Hello World!\n");` | 问候语与 Visual Studio 的进程退出提示之间隔一行空白。 |
| 08:32 | `printf("Hello World!");` | 问候语仍然完整，退出提示紧跟在下一行，两者之间的空白行消失。 |

讲师随后把 `\n` 加回。两次运行时程序输出只相差一个换行，退出提示由 Visual Studio 另行显示。

## 输入、输出和头文件（08:50–11:00）

讲师另开 Windows 命令提示符，在提示符后敲入字符说明“从键盘输入”，再指着窗口已有文字说明“输出”。这段操作发生在命令提示符中。回到 `hello.c`，程序只调用了输出函数 `printf`。

讲师把 `<stdio.h>` 比作修自行车时带的工具箱。包含它后可以使用其中声明的函数，至于程序是否打印，取决于是否执行了输出操作。他口头讨论了删去头文件的情形，演示中保留了 `#include <stdio.h>`。[Microsoft Learn · printf 的声明与所需头文件](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/printf-printf-l-wprintf-wprintf-l?view=msvc-170#requirements)

## 上机练习（11:00–13:15）

先完整看一遍，能看清每个标点，再关掉对照，在电脑上把八行程序独立敲至少十遍。讲师给的标准是能稳定写对、运行并看到预期输出。十遍后仍出错，就继续练。

末段有两种容易混淆的现象。讲师把入口名改成 `mian` 时，画面仍显示 `No issues found`。把 `printf` 行末的英文分号换成中文全角分号时，编辑器出现红色波浪线，错误计数变为 1。两个错例都只演示到编辑阶段，最后源码恢复。自己练习时，先检查 `main`、`return` 和英文标点，再运行并核对输出。

讲师用 Visual Studio 编写并运行程序。他还提到 Dev-C++、Xcode，以及可以自行搭配 Clang 或 GCC 的 VS Code。这些工具在片中没有配置或运行。
