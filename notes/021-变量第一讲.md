# 021 · 变量第一讲：用阳光点数理解变量、类型和当前值

课堂演示的《植物大战僵尸》第一关有 150 点初始阳光。种一株豌豆射手花 100 点，捡一份阳光加 25 点。种一株、捡两份、再种一株，同一个计数依次显示 **150 → 50 → 75 → 100 → 0**。

**用 C 表示一次拾取（整理者举例）**

```c
int sun = 50;
sun = sun + 25;
```

`sun` 是变量名，`int` 是它的整数类型，`50` 是初值。第二行先取出 50，加 25，再把 75 写回 `sun`。变的是当前值，声明的类型始终是 `int`。[C 标准委员会草案 §6.5.16.1 简单赋值](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=120)

**读数能支持哪些判断**

- **区分游戏规则和类型。** 第二株种下后剩 0 点，讲师说的“正整数”应改为“非负整数”。`int` 本身允许负数。自己写种植逻辑时，要先判断 `sun >= 100`，阳光足够才扣点。
- **辨认计数。** 课堂中有 520 处数据同时等于 75，单看一次读数无法辨认阳光。种植后从 9990 降至 9890、拾取后又升至 9915 的那一项，同时符合扣 100 和加 25 两条规则。
- **判断上限。** 工具显示 1000000 后，种植时游戏先显示 999900，随后显示 **9990**。讲师念成了 9900，并推测上限约为一万。课堂未测试一万附近的临界值，精确上限仍未知。
- **判断类型。** 同一个冷却进度条既可以按整数帧数更新，也可以按带小数的秒数更新。只看卡片变亮的过程，无法确定程序用了哪种类型。
