# 021 · 变量第一讲：用阳光点数理解变量、类型和当前值

《植物大战僵尸》第一关开场有 **150** 点阳光。种一株标价 100 的豌豆射手，计数变成 **50**。捡两次阳光，先到 **75**，再到 **100**，正好够种第二株。种下去，计数变成 **0**。四次操作更新的都是同一个量。讲师画的购物篮一次只装一瓶饮料，对应的是一个变量在某一时刻只有一个当前值。

## 把阳光点数写成 C 变量

在 `int sun = 50;` 中，`sun` 是变量名，以后用这个名字就能读取或更新这份点数。`int` 是声明的类型，表示用整数保存点数。`50` 是初始值。执行 `sun = sun + 25;` 时，先用右边的旧值算出 75，再把 75 写回左边的 `sun`。下次读取就得到 75，变量的类型仍是 `int`。[C 标准委员会草案 §6.2.5 类型](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=57) · [§6.5.16.1 简单赋值](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=120)

**整理者练习。** 课堂演示用的是游戏，下面的 C 程序从种完第一株时的 50 点开始。把它放进 C 控制台项目的 `.c` 文件，先写下你预计看到的四个数，再编译运行。[第 001 节的项目建立与运行方法](001-第一个程序.md)

```c
#include <stdio.h>

int main(void)
{
    int sun = 50;
    printf("%d ", sun);

    sun = sun + 25;
    printf("%d ", sun);

    sun = sun + 25;
    printf("%d ", sun);

    sun = sun - 100;
    printf("%d\n", sun);
    return 0;
}
```

输出应为 `50 75 100 0`。每个 `printf` 都在读当时的 `sun`，`%d` 把这个 `int` 值按十进制显示。把初始值改为 75，再运行会得到 `75 100 125 25`。两次拾取和一次种植的规则都相同，改变起点就能预测整串读数。

## 从界面读数能判断到哪一步

- **能取哪些值。** 讲师口头称阳光为“正整数”，但种完第二株时画面明确显示 0。本例观察到的是**非负整数**，包括 0。练习选用的 `int` 也能表示负数。如果自己写游戏，规则要求阳光不够就不能种，那么应在扣 100 前判断 `sun >= 100`。
- **变化由什么触发。** 课堂中，一度有 520 处数据都等于 75。一个数碰巧相同，很难说明它代表阳光。可以用一次种植和一次拾取作判断。第一关后段的读数从 9990 降到 9890，又升到 9915，两次变化都与已知的花费和收入吻合。
- **游戏规则和类型范围。** 工具曾显示 1000000，种植后游戏先显示 999900，随后显示 **9990**。讲师念作“9900”，并猜测上限约为一万。课堂没有测试临界值或查看源码，精确上限和游戏实际声明的类型都未确认。在第二关，工具和游戏都显示过 9998，随后正常种植仍会扣点。
- **界面如何显示，源码如何保存。** 讲师指着植物卡片讨论种植后的冷却。只看冷却进度，看不出程序保存的是整数帧数还是带小数的时间。课堂没有测量或改动冷却。讲师还用金额举例。即使屏幕显示 300.31 元，程序也可以保存整数 30031 分，再换算成元显示（整理者举例）。课堂没有检查支付软件的实现。

片末讲师还提到单个字符和一段话。选类型时可以从用途入手。阳光点数要做加减，本例用 `int` 保存。单个英文字母可以用 `char` 保存，一段提示文字则可以用以空字符 `'\0'` 结尾的 `char` 数组保存。[C 标准委员会草案 §7.1.1 字符串](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=198)
