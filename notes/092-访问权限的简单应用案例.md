# 092 · 同一套访问规则，何时用分支，何时合成一个布尔值？

用职位、已完成任务数和经理是否批准，判断一名员工能否访问资源。职位变量 `role` 的三个取值决定适用哪条规则。

| `role` | 身份 | 允许访问的条件 |
| --- | --- | --- |
| 1 | 经理 | 无条件允许 |
| 2 | 普通员工 | 已完成任务数 `> 5`，最少 6 项 |
| 3 | 实习生 | 已完成任务数 `> 10`，最少 11 项，且经理已批准 |

**先确定门槛是否包含等号。** 注释中写的是“5 个以上”。讲师先写 `>= 5` 和 `>= 10`，随后在运行前把两处都改成严格大于。若实际需求是“至少 5 项”或“至少 10 项”，对应位置应写 `>=`。

## 按输出需求选择写法

如果不同身份获准时要显示不同说明，用一条 `if / else if / else` 链，每个放行分支调用自己的 `puts`，都未命中就走最后的拒绝分支。课堂初版把任务数固定为 6、批准标志固定为 `false`，依次把职位改为 2、1、3 运行，结果分别是允许、允许、拒绝。员工提示写着“已经完成了五个任务”，这段固定文字不会随 `completed_tasks` 的值变化。

如果调用方只需要“允许”或“拒绝”，可以将每种身份的放行条件括成一组，组内用 `&&`，三组之间用 `||`。下面按课堂第二版整理。保存为 `.c` 文件，更改三个初值后编译运行即可核对结果。

```c
#include <stdio.h>
#include <stdbool.h>
#include <inttypes.h>

int main(void) {
    uint8_t role = 2;
    uint8_t completed_tasks = 6;
    bool is_manager_approved = false;

    bool access_allowed =
        (role == 1) ||
        (role == 2 && completed_tasks > 5) ||
        (role == 3 && completed_tasks > 10 && is_manager_approved);

    if (access_allowed) {
        puts("允许访问");
    } else {
        puts("拒绝访问");
    }
    return 0;
}
```

批准标志只在实习生这一组里。若把它放到整个表达式外面，用 `&& is_manager_approved` 约束全部三组，就会连经理和普通员工也要求先获批。当 `role == 1` 时，`||` 已经得到真值，会跳过后面两组。初版的经理分支命中后同样会跳过后续 `else if`。[C 逻辑运算符](https://learn.microsoft.com/zh-cn/cpp/c-language/c-logical-operators?view=msvc-170) · [C 的 if 语句](https://learn.microsoft.com/zh-cn/cpp/c-language/if-statement-c?view=msvc-170)

讲师给合并写法的适用条件是身份固定、条件少、只需统一输出。如果还要频繁增加职位，可以把各项规则单独列出来逐项检查。他预告后续可以用数组存放规则，本节没有实现。

## 用临界值验证结果

讲师写完第二版后没有在录屏中再次运行。整理者运行上面的程序，保持普通员工未获批，把任务数从 5 改为 6，输出从“拒绝访问”变为“允许访问”。实习生即使获批，10 项仍被拒，11 项才获准。保持 11 项，只把批准标志改回 `false`，结果又变为拒绝。
