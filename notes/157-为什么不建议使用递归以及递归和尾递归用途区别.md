# 157 · 普通递归、尾递归和循环，应该怎样选？

先看每层返回后还有什么工作，再估计最坏情况下会同时等着多少层调用。

- **一个问题自然分成多个子问题，而且返回后还要合并结果**，普通递归容易对应算法本身。例如树遍历需要处理各个子树。需要评估的是同一时刻尚未返回的最大深度；一万条独立订单并不自动意味着一万层调用。
- **每次只进入一个更小的问题，过去的工作能浓缩成累计值**，可以写成尾递归。录屏中的阶乘把普通写法的 `n * factorial(n - 1)` 改为 `factorial(n - 1, n * acc)`，让下一层接收已算好的乘积。阶乘的初始 `acc` 取 1，终止时必须返回 `acc`。
- **深度可能很大，又必须控制调用栈**，对这样的线性累积直接用循环。尾递归经优化后可能复用栈帧；C 程序不能仅凭 `return f(...)` 保证这么执行。GCC 提供 `-foptimize-sibling-calls`，录屏没有对任一编译器做性能、栈深度或生成代码的测量。[GCC 优化选项](https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html#index-foptimize-sibling-calls)

**用一组参数查清累计值。** 片中注明 `factorial(5, 1) → (4, 5) → (3, 20) → (2, 60) → (1, 120) → (0, 120)`。最后一层返回 120。如果将基例错写成 `return 1;`，此前累积到 120 的结果便全部丢掉。这里的 120 来自源码和推演，课堂没有运行结果窗口。
