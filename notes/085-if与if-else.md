# 085 · 何时写两个 if，何时用 else？

## 看两个动作能否同时发生

| 需要的行为 | 写法 | 课堂验证 |
| --- | --- | --- |
| 满足条件才做一件事 | 单个 `if (number > 10)` | `number` 为 `100` 时打印“大于10”的提示，改为 `1` 后没有程序输出 |
| 两条规则分别判断，允许两条都执行 | 先写 `if (number > 10)`，再单独写 `if (number >= 100)` | `100` 打印两条提示，`99` 只打印“大于10” |
| 两种结果只选一个 | `if (number > 10) { ... } else { ... }` | `99` 走 `if`，`1` 走 `else`。按同一条件推算，恰好 `10` 也走 `else` |

课堂切换测试值时，直接修改源代码里 `uint32_t number` 的初值再运行。在第二种写法中，即使第一个条件成立，程序仍要检查第二个条件。如果误把第二个 `if` 换成 `else`，`100` 就只会打印第一条，丢掉本该出现的第二条提示。

## 看花括号决定哪条语句归分支管

下面保留课堂最后的判断与三条打印语句，可以直接编译。运行一次，再把初值从 `100` 改成 `1` 重新运行。

```c
#include <stdint.h>
#include <stdio.h>

int main(void) {
    uint32_t number = 100;

    if (number > 10) {
        printf("这个数大于10!\n");
    } else {
        printf("这个值小于等于10!\n");
    }
    printf("111111111111!\n");
    return 0;
}
```

两次运行的第一行随条件改变，第二行都是 `111111111111!`。最后一个 `printf` 在 `else` 的右花括号之后，走完任一分支都会到达它。若只想在 `number <= 10` 时打印这串数字，就把最后一个 `printf` 移进 `else` 的花括号。

省略花括号时，`if` 或 `else` 各自只控制紧跟的一条**语句**，换行和缩进都不会把第二条 `printf` 收进去。遇到嵌套时，`else` 与语法上最近、尚未配对的 `if` 结合。讲师建议即便只有一条语句也保留花括号，方便以后增加第二条。[微软 C 语言参考：if 语句](https://learn.microsoft.com/zh-cn/cpp/c-language/if-statement-c?view=msvc-170)

## 检查括号里究竟测了什么

- **数值条件看是否为零。** `number > 10` 的比较结果为 `1` 表示真，为 `0` 表示假。课堂把条件临时改成 `if (10)` 和 `if (19999)`，两次都打印了原提示，因为这两个常量非零。此时程序已不再比较 `number`。讲师口头提到的“大于等于一”只覆盖部分真值。整理者用 `if (-1)` 和 `if (0.5)` 复核，两者都进入真分支。[C11 草案 §6.8.4.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=166)
- **条件必须反映真实数据。** 讲师用 `if ("如果今天天气晴朗")` 示意“晴天骑车，否则乘公交”，随后删去了这段代码。按 C 规则，这个字符串在条件中会转换为指向首字符的非空指针，条件恒真。整理者的写法是先把天气判断结果存入变量 `is_sunny`，再用 `if (is_sunny)` 选择行动。[C11 草案 §6.3.2.1](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=72)
