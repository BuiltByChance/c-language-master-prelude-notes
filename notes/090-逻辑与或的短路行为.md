# 090 · 逻辑与、逻辑或什么时候会跳过右侧条件？

在 C 里，条件值为零表示假，非零表示真。`A && B` 要求两项都为真，所以 `A` 为假就得到 `0`。`A || B` 只要求至少一项为真，所以 `A` 为真就得到 `1`。这两种情况下都跳过 `B`，即使 `B` 是函数调用。这就是短路。单个 `&`、`|` 做按位运算，没有这种短路规则。[C11 草案 §6.5.13–14](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=117)

## 活动不能举行时，怎样列全原因？

高尔夫活动要求天气晴朗且场地可用。下面沿用课堂最终的判断，把两个初值都设为 `false`。改动初值后重新运行，可逐项核对失败原因。

```c
#include <stdbool.h>
#include <stdio.h>

int main(void) {
    bool is_weather_sunny = false;
    bool is_venue_available = false;

    if (is_weather_sunny && is_venue_available) {
        printf("如期举行！\n");
    } else {
        printf("活动无法举行！\n");
        if (!is_weather_sunny) {
            printf("原因：天气不晴朗！\n");
        }
        if (!is_venue_available) {
            printf("原因：场地不可用！\n");
        }
    }
    return 0;
}
```

两项都为假时，外层 `&&` 读到天气为假就结束。进入 `else` 后的两个 `if` 是两次新的判断，所以控制台仍会列出天气和场地两个原因。若把第二个 `if` 接成 `else if`，天气为假时就会漏报场地。课堂实际运行了三种失败组合，控制台分别列出了场地、天气以及两项原因。

## 只要满足一项就能出门，该怎么写？

课堂用 `has_coupon || is_special_event` 判断是否出去吃饭。有优惠券时已经可以决定出门，右侧的饭店活动条件会被跳过。没有券时才看活动，有活动也出门，两项都没有才在家吃。讲师实跑了“有券、无活动”和“无券、无活动”，分别得到“决定出去吃饭”和“在家吃饭”。

这段代码初次构建时把 `printf` 写成了 `prinf`。遇到同样的 `LNK2019`，先看“未解析的外部符号”后面写的是哪个名字。本例中正是 `prinf`，补上 `t` 后重新构建才得到上述输出。[Microsoft Learn · LNK2019](https://learn.microsoft.com/zh-cn/cpp/error-messages/tool-errors/linker-tools-error-lnk2019?view=msvc-170)

## 怎样直接观察右侧有没有执行？

课堂控制台显示的是活动或用餐的决定。下面是整理者的复核程序，右侧函数每次被调用都会打印一行。

```c
#include <stdio.h>

int check_right(void) {
    puts("检查了右侧");
    return 1;
}

int main(void) {
    int left = 0;
    printf("与的结果 = %d\n", left && check_right());
    printf("或的结果 = %d\n", left || check_right());
    return 0;
}
```

`left = 0` 时，先看到“与的结果 = 0”，随后才是“检查了右侧”和“或的结果 = 1”。改为 `left = 1` 再运行，“检查了右侧”移到“与的结果 = 1”之前，打印“或的结果 = 1”时不会再次调用它。
