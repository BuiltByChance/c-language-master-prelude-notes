# 105 · 贩卖机一直要求投币，怎样查出是 while 还是 if 写错了？

这台贩卖机售价 5，只收面额为 1、2、5 的硬币。`coin` 是刚投入的一枚，`balance` 是已经收下的总额。看到“钱不够，请投币”重复出现时，先问**上一次投的币该不该入账，入账后够不够 5**。

## 从屏幕现象找到该查的语句

| 现象 | 下一步检查 |
| --- | --- |
| 一次投币提示都没有就跳过循环 | 把初值代入 `while (balance < PRICE)`。初始余额为 0、售价为 5，`0 < 5` 应为真。若把“够钱出货”写成继续条件，就会在第一轮前跳过收款 |
| 合法硬币也触发“拒收” | 投一枚 1，把 1 代入循环体内的 `if`。若写成 `coin == 1 && coin == 2 && coin == 5`，同一枚硬币永远无法满足三个等式，`balance += coin` 就没有执行机会 |
| 收币分支已执行，程序仍要求投币 | 在 `balance += coin` 后看本次面额和更新后的总额。若余额没增加，检查累加语句更新了哪个变量。余额增加到 2 时应该再问。若余额恰好为 5 还再问，检查下一轮 `while` 读的是哪个变量、用的是 `<` 还是 `<=` |

## 用一条测试输出验证判断

可在第 104 节的程序中复现。把投币判断的两个 `||` 临时改为 `&&`，在收币分支的 `balance += coin;` **之后**插入下面这行，保留原有的余额输出。整理者用 `<inttypes.h>` 的 `PRIu32` 打印 `uint32_t` 类型的面额。[第 104 节完整程序](104-自动贩卖机案例.md)

```c
printf("[收币分支] coin=%" PRIu32 "\n", coin);
```

1. 在 Visual Studio 的“调试”菜单选择“开始执行（不调试）”（`Ctrl+F5`），输入 `1`。若出现“拒收 1”，却没有测试行，两条线索合起来说明本轮进入了 `else`。此时先检查 `if` 的条件，修改分支内的加法不会改变执行路径。
2. 将条件恢复为 `coin == 1 || coin == 2 || coin == 5`，重新运行。依次投 1、2，录屏中测试行分别显示 1、2，余额分别为 1、3。此时再次提示投币符合 `3 < 5`，这次演示就停在这里。
3. 整理者补测时又投了 2，余额到 5，程序提示取饮料并结束。查完后注释掉临时测试行，保留用户需要的余额提示。

## 让下一次排查更快

- 在 Visual Studio 中，把鼠标停在 `PRICE` 上可查看声明和注释。全大写是命名约定，本例的售价只读来自声明 `const uint32_t PRICE = 5;`。用变量名说明“本次面额”和“累计金额”的区别，把注释留给“键盘输入模拟投币”这类从代码本身看不出的假设。[Microsoft Learn《类型限定符》](https://learn.microsoft.com/zh-cn/cpp/c-language/type-qualifiers?view=msvc-170)
- 处理大量数据时，分开看**要遍历多少项**和**每一轮做了多少工作**。数据的组织方式会影响要遍历的项数。检查循环体时，若某项计算的结果不随轮次改变，且提前计算不会改变程序行为，就可以在循环外算一次。读取下一枚硬币则必须留在循环内。
