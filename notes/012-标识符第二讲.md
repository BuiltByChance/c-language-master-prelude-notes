# 012 · 标识符第二讲：有效字符、大小写与保留名称

给变量或函数起名时，要看两个名字从哪里开始不同、字母大小写是否一致，以及这个拼法是否留给了编译器或标准库。课堂用两个只在末尾不同的名字解释“有效字符”，随后在微软的头文件里找到了保留名称的真实例子。

## 两个长名字从哪里开始不同（00:00–05:08）

讲师在 **Microsoft Learn → C 语言参考 → C 的元素 → C 标识符** 选中 `ANSI`，又用记事本把它和 `ASCII` 对照。ANSI 是美国国家标准协会，ASCII 是字符编码。字幕里的“NC”指画面上的 ANSI。[ANSI 官方简介](https://www.ansi.org/about/introduction) · [微软《C 标识符》](https://learn.microsoft.com/zh-cn/cpp/c-language/c-identifiers?view=msvc-170)

在 Visual Studio 的 `001.c` 中，讲师把 `main` 里的一个局部变量名拉长，复制整行，再给第二个名字追加数字。他选中共同的开头，假设识别范围恰好到第 31 个字符。记事本里的“张三你”和“张三你好”只差末尾一个字。如果名单只核对前三个字，末尾的“好”就帮不上忙。课堂说的 31、40、41 是对示例长度的假设，画面没有计数或编译结果。

讲外部名称时，他先用身份证号码打比方，再写下 `myGlobalVar1` 和 `myGlobalVar2`。两者前六个字符都是 `myGlob`。对照 C 标准，这里的“外部”指**具有外部链接**，即不同翻译单元里的声明可以指向同一对象或函数。仅凭声明写在函数外，还不能判定它具有外部链接，例如，按标准定义，文件作用域的 `static` 函数就具有内部链接。课堂只在记事本演示了前缀。[WG14 C11 草案 §6.2.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=54)

**标准核对。** 对本课的英文字母和数字，下表是实现至少需要支持区分的开头字符数。实现可以支持更多。

| C 标准 | 内部标识符 | 外部标识符 |
| --- | ---: | ---: |
| C89/C90（课程引用的数字） | 31 | 6 |
| C99、C11 | 63 | 31 |

“内部”在这项限制里包括没有外部链接的标识符，宏名也适用内部的数字。倘若两个名字的差别确实全部落在某个实现不区分的位置，C11 规定行为未定义，不能据此断言它们一定成为同一个变量。移植程序时，把区别放在名字靠前的位置，就不必依赖很长的共同前缀。[C89 委员会说明 §3.1.2](https://www.open-std.org/Jtc1/sc22/WG14/www/C89Rationale.pdf#page=26) · [C99 委员会说明 §6.4.2.1](https://www.open-std.org/JTC1/sc22/wg14/www/docs/n897.pdf#page=45) · [C11 翻译限制](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=43) · [C11 标识符规则](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=78)

## 微软文档中的 247、2047 和 `/H`（05:08–06:33）

讲师圈出微软页面上的 **247**，点进 **/H（限制外部名称长度）**，滚过示例和项目属性说明，随后返回。247 说的是一个名字里的字符数。“一般人够用”是讲师的判断。课堂没有打开项目属性、设置 `/H` 或测量编译器的上限。

**微软文档核对（2026-11-19）。** 《C 标识符》仍写内部、外部名称可含 247 个字符，并称可用 `/H` 调大或调小。选项专页把外部（公共）名称的默认上限写为 **2047** 个字符，其中计入编译器添加的前缀。`/Hnumber` 只能调低这个限制，自 Visual Studio 2005 起已弃用。专页的 x86 示例使用 `/H5`，预期 `func1` 和 `func2` 会引发链接错误 `LNK2005`。这是文档给出的预期结果。2047 的说明限于外部名称。[微软《C 标识符》](https://learn.microsoft.com/en-us/cpp/c-language/c-identifiers?view=msvc-170) · [微软《/H（限制外部名称长度）》](https://learn.microsoft.com/zh-cn/cpp/build/reference/h-restrict-length-of-external-names?view=msvc-170)

## 大小写和保留名称（06:33–12:24）

- **大小写。** 网页列出的 `add`、`ADD`、`Add`、`aDD` 是四个不同的标识符。调用一个函数或引用一个变量时，照声明里的大小写拼写。讲师提到 Word 字号，画面实际是在记事本写“张三 15”和“张三 18”。改变编辑器字号不会改变源码里的名字。[微软《C 标识符》](https://learn.microsoft.com/zh-cn/cpp/c-language/c-identifiers?view=msvc-170)
- **下划线。** 讲师临时输入了 `int __PRINTR = 100;` 和一行 `#define` 草稿，后面又在函数内写到 `int _Apple`、`int _a` 就删去。按 C 标准，以双下划线或“下划线紧跟大写字母”开头的标识符始终保留给实现，因此 `__PRINTR` 和 `_Apple` 都应避开。`_a` 则要看声明在哪里。在文件作用域，普通标识符和结构、联合、枚举的标记名，只要以下划线开头就保留。课堂把 `_a` 写在函数块内，这条文件作用域规则并不适用。初学时自己命名，直接用字母开头就能避开这些保留前缀。讲师口头把它们归为微软专用，C 标准本身也有这些规定。[WG14 C11 草案 §7.1.3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=200)
- **头文件里的实例。** 在 `001.c` 选中 `printf` 并跳转到定义，`stdio.h` 里就能看到 `_Check_return_opt_`、`_CRT_STDIO_INLINE` 和 `__CRTDECL`。再跟到 `vadefs.h`，可以看到 `__crt_va_start` 的宏定义。现场确认的是微软头文件采用了这些拼法。对调用者公开的函数名 `printf` 由 C 标准库规定。[WG14 C11 草案 §7.21.6.3](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf#page=342)

## 本节学到哪里（12:24–14:38）

讲师从标识符页打开“生存期、范围、可见性和链接”总览，分别浏览“生存期”和“范围和可见性”，把详细解释留到后面。最后回到命名语法。讲师给初学者划出的重点是先会起名。在本课的基本字符范围内，名字以字母或下划线开头，后续可以加数字，使用时保持大小写一致。最后一次从 `printf` 跳到头文件又返回，`001.c` 留着 `printf("Hello, World!\n");` 和 `return 0;`，没有构建或控制台输出。
